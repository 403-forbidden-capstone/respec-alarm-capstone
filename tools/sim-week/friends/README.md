# sim-week/friends — 친구 · 그룹 · 권한 가상 유저 일주일

가상 유저 여럿(기본 6명)이 로컬 Supabase에 로그인해 7일 동안 하루 여러 번(기본 8번) 행동합니다. **모델 호출 0회.** 하루가 끝날 때마다 DB 전체를 읽어 규칙 위반을 셉니다. 끝나는 조건은 **권한 위반 0 · 이상 결과 0**(`친구_PR계획.md` 테스트 완료 2번).

```
cd tools/sim-week/friends
npm install
E2E_SEED_ENV=<supabase/seed/.env 경로> node run.mjs [--users 6] [--days 7] [--actions 8] [--seed 글자] [--report 경로]
npm test        # 난수 · 규칙 검사기 시험 (DB 없음)
```

- 필요: 로컬 스택(`npx supabase start`) + 시드 `.env`. `127.0.0.1`이 아니면 멈춤. `db reset` 안 함
- 시드 데모 계정은 안 건드림. 전용 임시 계정 `simfriend-…@example.com`과 이름이 `SIM `으로 시작하는 그룹 · 약속만 만들고, 끝나면(오류 포함) 지움. 지우기가 실패해도 다음 실행이 먼저 지움
- 같은 DB에서 이 도구를 두 개 동시에 돌리지 말 것(서로의 임시 계정을 지움)
- 환경 읽기 · 함수 이름은 `tools/friend-e2e`(`env.mjs` · `caps.mjs` · `rpc-map.mjs`)를 불러 씀

## 시작 상태

일주일 첫날부터 모든 기능이 일하도록 사람 만들 때 DB(admin)로 미리 둠: 시작 그룹 둘(사람 0~3 · 2~5, 기상 공유 동의는 사람마다 다름), 받은 그룹 초대 몇 개, 친구 0-1 · 1-2 · 2-3(수락) + 4→0(요청 대기), 설정 권한까지 준 1→0 · 2→1, 그룹 A의 공동 약속(0~3이 기상 알람 · 출발 알람 보유). 이 줄들도 `SIM ` 접두 · 임시 계정이라 끝나면 지워짐.

## 하는 행동 (DB에 있는 기능만 자동으로 들어감)

아이디 검색 · 친구 요청 · 수락 · 거절 · 취소 · 끊기 · 차단 · 차단 풀기 · 그룹 만들기 · 코드 미리보기 · 코드로 참여(옛 함수 · 5장 새 함수) · 그룹에 친구 초대 · 초대 수락 · 공동 약속 만들기 · 내 알람 만들기(참여) · 약속 빠지기 · 공동 약속 고치기 · 기상 확인 · 기상 숨기기/보이기 · 깨우기 판정(서버 전용 함수) · 알람 바꾸기 제안/응답 · 그룹 권한 저장 · 나가기 · 내보내기 · 알람 조회 권한 켜기 · 끄기 · 공유 알람 조회. 사람과 행동은 씨앗으로 고정된 난수가 고르고, 가중치는 `actions.mjs`. 장 PR이 머지돼 함수가 생기면 그 행동이 저절로 들어갑니다(`caps`로 확인). 새 행동(깨우기 · 알람 바꾸기 제안 등)은 `actions.mjs`에 한 줄 더하고, 새 규칙은 `oracle.mjs`에 더함.

## 규칙 검사 (`oracle.mjs`)

| 이름 | 검사 | 종류 |
|---|---|---|
| F | 친구 행: 자기 자신 없음 · 두 사람 사이 한 행 · 상태 값 · 수락 시각 · 100명 상한 | 위반 |
| B | 차단 쌍: 친구 행 · 공유 권한 없음, 서로 아이디 검색에 안 나옴, 차단당한 쪽 차단 목록에 안 보임 | 위반 |
| P | 친구 출처 권한은 수락된 친구 행에서 나옴, 권한 없는 공유 알람 조회는 0줄, 권한 있는데 안 보이면 이상 | 위반 · 이상 |
| G | 그룹은 내 멤버 행이 있는 곳만 보임(5장 함수가 DB에 있으면 참여 중인 곳만). 5장 이후엔 구성원 행도 내 행 + 참여 중인 그룹 것만, 그룹마다 참여 중 1명 이상 · 20명 이하, 한 사람 참여 그룹 10개 이하 | 위반 |
| W | 그룹 기상 줄: 내 줄 말고는 기상이 보이는 사람(둘 다 참여 중 · 주인이 그 그룹에 동의 · 주인이 나에게 숨기지 않음 · 차단 아님)만 있음. 깨우기 판정은 기상이 안 보이는 사이면 FORBIDDEN. 기상 확인은 알람이 울리는 날 하루 한 건 | 위반 |
| P | 설정 권한이 조회 없이 켜진 행 없음(설정⊂조회). 알람 바꾸기 제안은 주인이 설정 권한을 준 사람(차단 아님)만 OK. 친구가 바꾼 합계는 ±60분 | 위반 |
| 9 | 공동 약속은 만든 사람만 고침(만든 사람이 비면 참여자). 앞으로 약속의 참여는 그룹에 참여 중인 사람만 | 위반 |
| 서버 | 문서에 없는 상태 값, 서버 오류(정상 거절 42501 · 23505 등은 제외) | 이상 |

- 이 시험의 '권한 위반 0'은 정직한 행동 뒤에 규칙을 관찰한 결과입니다. 친구 아닌 사람에게 권한 행을 넣으려는 위조 같은 금지 행동을 일부러 시도하는 부분은 아직 없습니다(후속).
- **알려진 동작(KNOWN)**: 그룹장이 나간 뒤에도 자기 그룹이 보이는 것은 `groups.owner_id` 정책이 남아 있는 동안의 동작입니다(5장 '그룹장 없음'에서 사라짐). 위반으로 세지 않고 보고서에 따로 적습니다. 5장 함수가 DB에 들어오면(만든 사람의 읽기 예외가 '만든 같은 트랜잭션'뿐) 나간 뒤에 보이는 것은 곧바로 위반으로 셉니다(`owner_id`가 없어 그룹장 판정이 불가능하므로 `visible` 그룹이 곧 위반).

## 검사량 문턱

기능이 조용히 빠져서 '위반 0'이 빈 검사로 나오지 않게, DB에 그 기능이 있는데 일주일 동안 한 번도 일어나지 않으면 이상(`검사량 부족`)으로 셉니다: 공유 알람 조회 보임 ≥1 · 안 보임 ≥1, 조회 권한 켜기 ≥1, 그룹 만들기 ≥1, 친구 수락 ≥1, 차단 쌍 검색 검사 ≥1, 검색 대조군(차단 안 한 사람이 FOUND) ≥1. 하루 끝 검사 전에 가상 유저의 검색 제한 기록(`rate_limit_events`)을 비워 제한에 걸려 검사가 비지 않게 합니다. 같은 씨앗이어도 DB 순서 · uuid · 시간 때문에 결과가 똑같지는 않으니 위반을 재현할 땐 보고서의 행동 기록을 보세요.

## 아직 안 하는 것

금지 행동 일부러 시도(위조 insert · 남의 표 직접 조회 · 그룹 출처 권한) · 깨우기 · 기상 확인 · 알람 바꾸기 제안 · 공동 약속 · 탈퇴(7 · 8 · 9 · 10 · 12장 함수가 생기면 행동과 규칙을 더함), 푸시 도착, 화면.

## 닿지 않는 것

기본 6명 × 7일 설정에서는 그룹 참여 20명 · 한 사람 10개 상한과 서버의 `FULL` · `TOO_MANY_GROUPS` 응답에 닿지 않습니다(규칙 검사 코드는 있지만 빈 검사). 상한을 보려면 `--users`를 크게 하는 별도 시나리오가 필요합니다(후속). 도구는 한 번에 한 실행만 돌리세요.
