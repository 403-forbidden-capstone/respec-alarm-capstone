# sim-week/friends — 친구 · 그룹 · 권한 가상 유저 일주일

가상 유저 여럿(기본 6명)이 로컬 Supabase에 로그인해 7일 동안 하루 여러 번(기본 8번) 행동합니다. **모델 호출 0회.** 하루가 끝날 때마다 DB 전체를 읽어 규칙 위반을 셉니다. 끝나는 조건은 **권한 위반 0 · 이상 결과 0**(`친구_PR계획.md` 테스트 완료 2번).

```
cd tools/sim-week/friends
npm install
E2E_SEED_ENV=<supabase/seed/.env 경로> node run.mjs [--users 6] [--days 7] [--actions 8] [--seed 글자] [--report 경로]
npm test        # 난수 · 규칙 검사기 시험 (DB 없음)
```

- 필요: 로컬 스택(`npx supabase start`) + 시드 `.env`. `127.0.0.1`이 아니면 멈춤. `db reset` 안 함
- 시드 데모 계정은 안 건드림. 전용 임시 계정 `simfriend-…@example.com`과 이름이 `SIM `으로 시작하는 그룹 · 약속만 만들고, 끝나면(오류 포함) 지움. 지우기가 실패해도 다음 실행이 먼저 지움
- 환경 읽기 · 함수 이름은 `tools/friend-e2e`(`env.mjs` · `caps.mjs` · `rpc-map.mjs`)를 불러 씀

## 하는 행동 (DB에 있는 기능만 자동으로 들어감)

아이디 검색 · 친구 요청 · 수락 · 거절 · 취소 · 끊기 · 차단 · 차단 풀기 · 그룹 만들기 · 코드로 참여 · 나가기 · 내보내기 · 알람 조회 권한 켜기 · 끄기 · 공유 알람 조회. 사람과 행동은 씨앗으로 고정된 난수가 고르고, 가중치는 `actions.mjs`. 장 PR이 머지돼 함수가 생기면 그 행동이 저절로 들어갑니다(`caps`로 확인). 새 행동(깨우기 · 알람 바꾸기 제안 등)은 `actions.mjs`에 한 줄 더하고, 새 규칙은 `oracle.mjs`에 더함.

## 규칙 검사 (`oracle.mjs`)

| 이름 | 검사 | 종류 |
|---|---|---|
| F | 친구 행: 자기 자신 없음 · 두 사람 사이 한 행 · 상태 값 · 수락 시각 · 100명 상한 | 위반 |
| B | 차단 쌍: 친구 행 · 공유 권한 없음, 서로 아이디 검색에 안 나옴, 차단당한 쪽 차단 목록에 안 보임 | 위반 |
| P | 친구 출처 권한은 수락된 친구 행에서 나옴, 권한 없는 공유 알람 조회는 0줄, 권한 있는데 안 보이면 이상 | 위반 · 이상 |
| G | 그룹은 내 멤버 행(초대 · 참여)이 있는 곳만 보임 | 위반 |
| 서버 | 문서에 없는 상태 값, 서버 오류(정상 거절 42501 · 23505 등은 제외) | 이상 |

- **알려진 동작(KNOWN)**: 그룹장이 나간 뒤에도 자기 그룹이 보이는 것은 `groups.owner_id` 정책이 남아 있는 동안의 동작입니다(5장 '그룹장 없음'에서 사라짐). 위반으로 세지 않고 보고서에 따로 적습니다. 5장 뒤에도 나오면 위반으로 바뀝니다(`owner_id`가 없어 그룹장 판정이 불가능하므로 `visible` 그룹이 곧 위반).
