#### 1. 시간표 한 번에 등록

- **A. 캡처 → AI 추출** — 시간표 앱 캡처 → AI로(지금은 Claude API, Gemini는 나중) 과목 · 요일 · 시각 · 건물 추출 → 확인 화면 → 요일 반복 약속 생성 (대화 일정 추출 흐름 재사용)
- **B. 요일 · 교시 입력 화면** — AI 없이 표에서 고름
- **C. 지금처럼 하나씩** (지금 코드)
- **D. 폰 캘린더에서 가져오기** — 구글 캘린더 등 폰 캘린더의 반복 수업을 후보로 보여 주고 확인하면 반복 일정으로 (설계서 선택 기능)

정함: A + D 둘 다 — 각 화면을 따로 만듦 (10/29 김지형 직접 "a, d 두 개 다 개발하자, 각 화면 만들어서")

기본안(지금 개발): 정함 A + D 따름 — A 캡처 → Claude로 읽기 → 확인 화면 → 반복 일정, D 폰 캘린더 → 후보 화면 → 반복 일정. 사진 고르기 · 캘린더 읽기 네이티브 패키지는 11/5 동결 전, 화면은 아침 한 바퀴 뒤. B 직접 입력 초안(L7 PR 5)은 계획에 남겨 둠

### D112 자동 예측 축소 상수 k — 10 vs 5

- 출처: 기록 · 제안 파트 가상 유저 실험 (11/9)
- 이슈: #32
- 기능: 알람 (C05)
- 기한: 다음 팀 회의 (D113과 같이)

#### 무슨 상황

자동 예측은 기록 수 n에 따라 공통 P80과 내 P80을 n/(n+k)로 섞음. 코드는 k = 10, 설계 문서(7장 7.2)는 K = 5 (`supabase/functions/_shared/calc/prepare.ts` 주석 "D56"이지만 D56 본문에는 이 질문이 없음). 최근 30건만 배우므로 k = 10이면 가중치가 30/40 = 0.75를 넘지 못해, 공통값에서 먼 사람은 차이의 25%가 계속 남음.

#### 선택지

- **A. 10 유지** (지금 코드)
- **B. 5** (설계 문서)

실험(가상 유저 8명 · 12주 · 시드 50, 제안 없이): 출발 지연 56% → 43%, 분위 손실 4.8 → 3.5. 제안을 잘 안 받는 사람(수아 60분)도 79% → 61%. 학습 기간을 30 → 60건으로 늘리는 건 효과가 작음. 기본안 제안: B — 단 k만 낮추면 제안과 합쳐 두 번 반영되므로 D113과 같이 정함. 준비 시간 ML 모델(`prepare_ml_*`)로 자동 예측을 바꾸는 계획이 있으면 그쪽과 먼저 맞춤

### D114 루틴 제안 — 무엇을 보고 · 언제 · 어디서 권할지

#### 1. 무엇을 보고 권하나

- **A. 늦어지는 원인별** — 기록에서 원인을 찾아 그에 맞는 짧은 루틴: 늦잠 · 다시 잠듦 → 일어나자마자 2단계, 준비를 늦게 시작 → 준비 알람 직후 첫 행동, 전날 준비 부족 → 전날 밤 준비 (D71 A의 루틴 부분)
- **B. 정해 둔 일반 루틴** — 명상 · 운동 같은 루틴을 모두에게 (D71 기본안 B)
- **C. AI가 대화에서 자유롭게** — 그날 대화 내용으로 AI가 루틴을 지어냄

기본안: A — 원인마다 이미 쌓이는 기록(기상 확인 · 미루기 · 미확인, 준비 시작 #490, 준비물 체크)으로 잴 수 있고, 근거 숫자("최근 7일 중 4일, 기상 알람 뒤 평균 18분")를 화면에 그대로 보여 줄 수 있음

#### 2. 문턱

- **A. 기록이 있는 최근 7일 중 3일** (슬라이드 v6)
- **B. 기록이 있는 최근 7일 중 4일**
- **C. 기록이 있는 최근 14일 중 6일**

기본안: B — 가상 유저 8명 × 12주 × 50번 실험에서 맞는 원인 88% · 놓침 0.5% · 원인 없는 사람이 엉뚱한 제안을 받는 비율 10%, 첫 제안은 평일 기록 11일째. A는 그 비율이 30%(원인 빈도를 1.4배로 가정하면 43%), C는 정확하지만 첫 제안이 17일째. 원인 빈도 가정을 ×0.6 · ×1.4로 흔들어도 B가 가장 균형이 맞음

#### 3. 알람 조정 제안과 나누기

- **A. 원인 하나에 처방 하나** — "준비가 길다"는 알람 조정 제안(D111)만, 그 밖의 원인은 루틴 제안만. 하루에 원인이 겹치면 늦잠 → 준비를 늦게 시작 → 준비가 길다 순서로 앞의 것 하나만 셈
- **B. 따로 판단** — 두 기능이 각자 판단해 같은 날 둘 다 제안할 수 있음

기본안: A — D62 "오차는 주원인 구간 한 곳"과 같은 원칙. 실험에서 판정 순서가 다른 원인을 가리지 않았음(준비를 늦게 시작 100% · 전날 준비 부족 98% 잡힘)

#### 4. 언제 · 어디서 묻나

- **A. 대화가 끝난 뒤 일기 화면에서만**
- **B. 매일 18:00 계산, 일기 화면 + 저녁 AI 대화 화면 카드** — 알람 조정 제안 카드(#528)와 같은 자리 · 방식, 둘 다 있으면 알람 조정이 먼저

### D115 아침 루틴 음성 진행 — 언제 · 어떻게 안내할지

- 출처: 루틴 파트 (기상 뒤 아침 루틴 수행, 11/2x)
- 이슈: #594 · #597 · #604
- 기능: AI · 루틴 (C20)
- 기한: 다음 팀 회의

#### 무슨 상황

기상 알람을 끈 뒤 아침 루틴을 하는 동안 AI가 단계를 안내하지 않았음 — 기상 확인 화면(H08)은 "홈으로"로 끝나고, 루틴은 홈 카드에서 손으로 체크. 서버 AI의 기상 후 대화(AFTER_WAKE)는 프롬프트에만 있고 앱에서 여는 곳이 없었으며, AI 맥락은 루틴 알람을 뺌. 그래서 "기상 확정 → AI가 루틴을 말로 한 단계씩 안내 → 사용자가 '했어' → 다음 단계"를 만들었고(#594 서버 · #597 앱 · #604 홈 입구), 그때 정한 것을 남김.

#### 1. 언제 시작하나

- **A. 버튼을 눌러야** — 기상 확인 화면에 "아침 루틴 시작" 버튼, 누르면 루틴 화면
- **B. 기상 확정 뒤 자동으로** — 오늘 아침 루틴에 남은 단계가 있으면 1.5초 뒤 루틴 화면(H09)이 열리고, [시작]을 한 번 누르면 AI가 말하기 시작

기본안: B — 작성자 결정, 팀 확인 필요. 아침엔 손이 덜 가게. 소리 · 마이크는 사용자가 한 번 눌러야 켤 수 있어 [시작] 한 번은 남김. 이미 확정된 화면을 다시 열면 이동하지 않음. 놓쳤으면 홈 "오늘 루틴" 카드 아래 "음성으로 진행 ›" (#604)

#### 2. 무엇으로 안내하나

- **A. 기기 음성 인식 + 정해진 말** — 안내는 TTS, 대답은 "했어 · 건너뛰기 · 잠깐"만 알아들음
- **B. Gemini Live** — 자기 전 대화와 같은 실시간 음성(1회용 토큰 · 연결 페이지)

기본안: B — 작성자 결정, 팀 확인 필요. 자기 전 대화도 Gemini Live라 연결 · 소리 · 마이크를 같이 씀. 토큰은 새 함수 `routine-live-token` — 지침(한 단계씩 · 확인 뒤에만 다음 · 끝나면 다음 알람 · 첫 일정으로 마무리)과 오늘 루틴 · 다음 알람을 토큰에 잠금

#### 3. 단계를 끝냈는지 어떻게 아나

- **A. 받아쓰기에서 낱말 찾기** — "했어" 같은 말이 나오면 다음 단계
- **B. AI 도구(function calling)** — AI가 사용자의 말을 알아듣고 `step_done(단계)` · `step_skipped(단계)` · `routine_finished()`를 불러 앱에 알림

기본안: B — 작성자 결정, 팀 확인 필요. "다 마셨어" · "끝" · "done"처럼 말이 달라도 AI가 판단. 앱은 지금 단계가 아닌 번호는 무시(같은 단계를 두 번 세지 않음)

#### 4. 음성이 안 될 때 · 기록

기본안: 화면의 [했어] · [건너뛰기]가 같은 일 — 누르면 기록하고 AI에게 앱 글로 알려 다음 단계로 넘어가게 함. 끝낸 단계는 그 단계 알람에 오늘 확인(ACKNOWLEDGED)을 남김 — 홈 "오늘 루틴" 카드와 같은 기록, 출처는 음성 VOICE · 버튼 BUTTON. 알람이 없는 단계는 남길 자리가 없어 화면에서만 셈(홈 카드와 같은 한계)

#### 5. 연결 유지

기본안: 30초 무발화로 끊는 규칙을 끔 — 단계를 하는 동안 몇 분씩 말이 없음. 10분 상한은 그대로, 끊기면 "음성 다시 켜기". 10분 넘는 루틴의 자동 재연결은 실기기 확인 뒤

- **C. 하루 점수** — 기상 · 출발 · 도착(지각) 합산, 70점 이상 = 목표 기상

- **A. 그대로 두기와 같음** (지금 코드) — 바깥을 누르면 취소, 여유도 원래 값
- **B. 시트만 닫음** — 바꾼 여유는 화면에 남고 저장은 안 된 상태, 다시 "저장"을 누를 수 있음

UI 점검 10/14: D43(확인 시트 안에서 바로 조정)을 고르면 이 시트 모양이 바뀌어 같이 다시 봄.

#### 2. 홈(H01) 오늘 루틴 카드를 다 끝낸 뒤 또 누를 때

홈 아침의 "오늘 루틴" 카드(차분한 출근 준비: 물 마시기 · 스트레칭 · 샤워 · 출발)는 누를 때마다 한 단계씩 완료로 줄이 그어짐. 4/4를 다 끝낸 뒤 또 누르면 지금은 0/4로 돌아감.

- **A. 처음으로 돌아감** — 잘못 눌렀을 때 되돌리는 길이 이것뿐
- **B. 다 끝나면 그대로** — 완료 표시 유지, 되돌리기는 따로(길게 누르기 등)

## 쓰는 법

- 새 안건: `## 정할 것` 아래에 `### D번호 질문`, 그 밑에 `- 출처:` · `- 이슈:` · `- 기한:` 줄
- 기능: `- 기능: 영역 (C05 · C03)` — 영역은 동작 표와 같은 다섯 중 하나(알람 / 그룹 · 친구 / 기록 · 제안 / AI · 루틴 / 기반 · 서버), 행은 동작 표 C01~C24. /decisions 묶음과 /board 동작 표 "관련 결정"이 이 줄을 읽음 (`npm run board:decisions`가 틀린 줄을 알려 줌). /decisions는 영역 안에서 기한에 "프로토타입 1차" 또는 "1차 데모"가 든 안건을 먼저 보임
- 세부: `#### 지금 어긋난 곳`(표 `| 어디 | 지금 |`) · `#### 선택지` · `#### 참고`
- 선택지 한 줄: `- **A. 이름** (먼저 고른 안) — 설명`, 할 일은 그 밑에 두 칸 들여 `- 할 일: …`
- 꼬리표: `(먼저 고른 안)` = 미리 골라 이슈에 적어 둔 안, `(지금 코드)` = 지금 코드가 이렇게 돎. 지금 코드가 어느 안과도 다르면 선택지 아래 "지금 코드: …" 한 줄
- 정하면: `- 결과:` 줄을 채우고 `## 정한 것`으로 옮김 → 이슈 본문 · docs도 고침
- 정한 것엔 `- 반영:` 줄 — 코드에 들어갔는지: `반영 전` · `반영 중 · PR #n` · `반영됨 · PR #n` · `코드 없음` (/decisions 라벨, 페이지에서 바꾼 라벨이 먼저 보임). 기준은 실데이터(로그인 뒤 앱) — 가짜 데이터에만 들어갔거나 일부만이면 반영 중. 정하면 결과와 다른 안의 `(지금 코드)` 꼬리표는 지움
- 결과가 길면 `- 결과:`엔 한 줄로 줄이고 세부는 `#### 정한 내용` 블록에 — 반영할 땐 이 블록대로 만듦
- /decisions에서 투표 · 직접으로 정한 것은 DB(decision_states · decision_comments)에 먼저 쌓임 → 문서 정리 때 `- 결과:`로 옮김
- 미룰 땐 `## 보류`로 옮기고 `- 보류 이유:` 줄
- 회의 전에 낸 의견: `#### 의견` 블록 (결과 아님, 정하면 지우고 `- 결과:`로)
- 상황 설명이 필요하면 `#### 무슨 상황` 블록 (어떤 화면에서 누가 무엇을 할 때인지)
- 정한 것을 다시 열 땐 `## 정할 것`으로 옮기고 `- 결과:` 줄은 지운 뒤 "출처"에 다시 연 이유(예: D20에서 다시)를 적음
- 번호는 다시 쓰지 않음 (보드가 펼침 상태를 번호로 기억함)
- 새 안건은 지형님 확인 뒤 올림 — 먼저 decisions.md · 상세설계서 · 회의 기록에서 답을 찾고, 이미 있는 안건이면 그 안건에 더함 (10/29 지형님). D72~D103은 10/29 레인 초안이 임시로 쓴 번호라(코드 주석 · PR에 남아 있음) 새 안건은 D104부터
- 기본안: `기본안(지금 개발): …` 줄 = 정하기 전에 개발이 따르는 안(결과 아님), 코드 주석은 "Dn 기본안"
- 10/29 개발 운영 줄임말: 레인 L1 아침 일정 · L2 위치 · L3 친구 · 그룹 · L4 AI · L5 UI 초안 · L6 결정 안건 · L7 온보딩 · 권한 · L8 실서버 · QA, `→ L1`은 반영할 레인. Q1~Q13 · N3~N6은 10/28 지형님께 드린 제안판 번호(친구 · 그룹 Q, 흐름 N — 10/29 지형님 "이대로")
- 새 안건은 질문 하나로 — 페이지 투표 3표 자동 정함은 질문 하나짜리 안건만 됨
- 여러 질문 안건은 질문별로 3표 이상인 질문만 정함 — 그 질문 선택지 아래 `정함:` 줄, 안건은 모든 질문이 정해질 때까지 정할 것에 남음 (10/29 지형님)
