- **C. 지금처럼 하나씩**

#### 2. 반복 일정 한 회차 예외

- **A. 이번만 건너뛰기 · 이번만 시각 변경 + 홈 "오늘 안 가요" 1탭** — 그날 알람 해제, 친구에겐 "오늘 일정 없음", 학습 제외

- **A. 회차 단위** — 회차 × 참여자로 기록, 하루 계획 단위(그날 첫 약속 기준 기상 하나 + 약속별 출발 · 도착), 휴강으로 첫 약속이 바뀌면 그날 다시 계산
- **B. 지금처럼** — 참여자 한 줄에 결과 한 세트

- 위 참고 표와 다른 점: 온보딩의 알람 권한 4개(정확한 알람 · 잠금화면 위 울림 · 배터리)를 첫날 받을지, 첫 알람을 만들 때 받을지

### D26 주간 점수 · 목표 기상 규칙

- 출처: PR #105 · UI 점검 (10/14)
- 이슈: #41 · #150
- 기능: 기록 · 제안 (C15 · C16)

#### 지금 어긋난 곳

| 어디 | 지금 |
|---|---|
| UI 점검 10/14 · 화면 R02 주간 | 막대는 점수만 — 날별 기상 시각이 안 보이고 70점 기준이 화면에 없음 |

#### 참고

R02 주간의 막대 점수와 "70점 이상이면 목표 기상" 규칙은 목업 값뿐이고 DB에 점수 칸이 없음. 점수 계산식 · 저장 여부(`daily_records`에 칸 추가 또는 그때그때 계산)를 정함. 목업은 지난 날 점수가 고정값이고, 오늘만 기상 확정이 기상 알람 + 10분 안이면 88점 · 넘으면 61점.

#### 선택지

- **A. 점수 없이 목표 기상 O/X** — 기상 확정이 기상 알람 + 10분 안이면 목표 기상. 막대 대신 날마다 O/X, 목표 기상률 = O 날 수 ÷ 기록한 날 수
- **B. 기상 점수** — 알람 시각보다 늦은 분만큼 깎음(예: 100 − 늦은 분 × 3), 70점 이상 = 목표 기상
- **C. 하루 점수** — 기상 · 출발 · 도착(지각) 합산, 70점 이상 = 목표 기상

지금 코드: 목업 점수 그대로 — 실데이터 · 가짜 오늘은 기상 확정이 기상 알람 + 10분 안이면 88점 · 넘으면 61점(가짜 지난 날은 고정 점수), 70점 이상 = 목표 기상, 저장 칸 없이 계산 (#168)

저장: 셋 다 `daily_records.wake_confirmed_at` · `is_late`로 그때그때 계산 가능 — 칸 추가는 계산이 무거울 때만.

#### 선택지 (단계 시각)

- **A. 시작 시각 칸 추가 + `offset` = 시작에서 몇 분 뒤** — 목업과 같음(21:30 시작 → 0 · 5 · 7분 뒤)
  - 할 일: `routines`에 시작 시각 칸(마이그레이션), 단계 시간을 바꾸면 뒤 단계 `offset`을 다시 계산
- **B. 단계마다 시각을 직접 저장** — `offset` 대신 `time`
  - 할 일: `steps` 모양 바꿈, 시작을 옮기면 단계 시각을 전부 같이 옮김
- **C. 기상 알람 기준 `offset`** — 아침 루틴이면 기상 + n분, 저녁 루틴이면 취침 기준
  - 할 일: 기준 알람(기상 · 취침)을 루틴에 연결하는 칸, 저녁 루틴 기준 시각 정의

지금 코드: 실데이터는 단계마다 시각을 `offset`(0시부터 분)에 저장, 첫 단계 `offset` = 시작 시각, 걸리는 시간은 단계 JSON에 `minutes` 키로 — B에 가깝게 임시 (#168)

#### 선택지 (반복 요일)

- **A. 요일 배열** — `{MON,WED,FRI}` (Postgres 배열), 화면 요일 버튼과 1:1
- **B. 문자열** (지금 코드) — 'MON~FRI' · 'MON,WED' 같은 형식을 정해 둠, 읽을 때 파싱

- **B. 안 넣음** — 사실은 알람 · 위치 자동 기록과 직접 입력만, 대화 내용은 회고 코칭에만 씀

## 쓰는 법

- 새 안건: `## 정할 것` 아래에 `### D번호 질문`, 그 밑에 `- 출처:` · `- 이슈:` · `- 기한:` 줄
- 기능: `- 기능: 영역 (C05 · C03)` — 영역은 동작 표와 같은 다섯 중 하나(알람 / 그룹 · 친구 / 기록 · 제안 / AI · 루틴 / 기반 · 서버), 행은 동작 표 C01~C24. /decisions 묶음과 /board 동작 표 "관련 결정"이 이 줄을 읽음 (`npm run board:decisions`가 틀린 줄을 알려 줌). /decisions는 영역 안에서 기한에 "1차 데모"가 든 안건을 먼저 보임
- 세부: `#### 지금 어긋난 곳`(표 `| 어디 | 지금 |`) · `#### 선택지` · `#### 참고`
- 선택지 한 줄: `- **A. 이름** (먼저 고른 안) — 설명`, 할 일은 그 밑에 두 칸 들여 `- 할 일: …`
- 꼬리표: `(먼저 고른 안)` = 미리 골라 이슈에 적어 둔 안, `(지금 코드)` = 지금 코드가 이렇게 돎. 지금 코드가 어느 안과도 다르면 선택지 아래 "지금 코드: …" 한 줄
- 정하면: `- 결과:` 줄을 채우고 `## 정한 것`으로 옮김 → 이슈 본문 · docs도 고침
- 정한 것엔 `- 반영:` 줄 — 코드에 들어갔는지: `반영 전` · `반영 중 · PR #n` · `반영됨 · PR #n` · `코드 없음` (/decisions 라벨, 페이지에서 바꾼 라벨이 먼저 보임). 기준은 실데이터(로그인 뒤 앱) — 가짜 데이터에만 들어갔거나 일부만이면 반영 중. 정하면 결과와 다른 안의 `(지금 코드)` 꼬리표는 지움
- /decisions에서 투표 · 직접으로 정한 것은 DB(decision_states · decision_comments)에 먼저 쌓임 → 문서 정리 때 `- 결과:`로 옮김
- 미룰 땐 `## 보류`로 옮기고 `- 보류 이유:` 줄
- 회의 전에 낸 의견: `#### 의견` 블록 (결과 아님, 정하면 지우고 `- 결과:`로)
- 상황 설명이 필요하면 `#### 무슨 상황` 블록 (어떤 화면에서 누가 무엇을 할 때인지)
- 정한 것을 다시 열 땐 `## 정할 것`으로 옮기고 `- 결과:` 줄은 지운 뒤 "출처"에 다시 연 이유(예: D20에서 다시)를 적음
- 번호는 다시 쓰지 않음 (보드가 펼침 상태를 번호로 기억함)
