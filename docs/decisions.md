### D5 카카오 응답을 어디까지 남길지

#### 무슨 상황

일정을 만들 때(H05) 서버가 카카오 대중교통 길찾기를 불러 이동 시간(분)을 받고, 기상 시각 = 약속 − 여유 − 이동 − 준비로 계산함. 이 응답에서 무엇을 DB에 남길지가 문제.

#### 지금 어긋난 곳

| 어디 | 지금 |
|---|---|
| 카카오 API 약관 | 응답 저장 · 재사용 불가 |
| DB `appointment_participants` | `est_travel_minutes`(경로 API 조회 결과) · `travel_source`(API · CACHED · MANUAL) 칸 있음 — CACHED = 저장해 둔 값을 다시 씀 |

#### 선택지

- **A. 계산에 쓴 분만 기록으로 남김** — 경로 · 원문은 안 남김. 다시 계산할 땐(반복 회차 · 여유 변경) 카카오를 다시 부름
  - 할 일: `travel_source` CACHED 안 씀, 반복 회차마다 호출 수 확인
- **B. 분을 남기고 반복 회차 · 재계산에도 그 값을 씀** (`travel_source = CACHED`) — 호출이 적음, 약관 '재사용'에 걸릴 수 있음
  - 할 일: 카카오에 "계산 결과(분)만 저장"도 재사용인지 문의
- **C. 아무것도 안 남김** — H03 계산식의 이동 분도 열 때마다 다시 부름
  - 할 일: `est_travel_minutes` 칸 비워 둠, 학습은 실측 이동 시간만 씀

#### 참고

R02 주간의 막대 점수와 "70점 이상이면 목표 기상" 규칙은 목업 값뿐이고 DB에 점수 칸이 없음. 점수 계산식 · 저장 여부(`daily_records`에 칸 추가 또는 그때그때 계산)를 정함. 목업은 지난 날 점수가 고정값이고, 오늘만 기상 확정이 기상 알람 + 10분 안이면 88점 · 넘으면 61점.

- **C. 하루 점수** — 기상 · 출발 · 도착(지각) 합산, 70점 이상 = 목표 기상

## 쓰는 법

- 새 안건: `## 정할 것` 아래에 `### D번호 질문`, 그 밑에 `- 출처:` · `- 이슈:` · `- 기한:` 줄
- 세부: `#### 지금 어긋난 곳`(표 `| 어디 | 지금 |`) · `#### 선택지` · `#### 참고`
- 선택지 한 줄: `- **A. 이름** (먼저 고른 안) — 설명`, 할 일은 그 밑에 두 칸 들여 `- 할 일: …`
- 꼬리표: `(먼저 고른 안)` = 미리 골라 이슈에 적어 둔 안, `(지금 코드)` = 지금 코드가 이렇게 돎. 지금 코드가 어느 안과도 다르면 선택지 아래 "지금 코드: …" 한 줄
- 정하면: `- 결과:` 줄을 채우고 `## 정한 것`으로 옮김 → 이슈 본문 · docs도 고침
- 정한 것엔 `- 반영:` 줄 — 코드에 들어갔는지: `반영 전` · `반영 중 · PR #n` · `반영됨 · PR #n` · `코드 없음` (/decisions 라벨, 페이지에서 바꾼 라벨이 먼저 보임)
- /decisions에서 투표 · 직접으로 정한 것은 DB(decision_states · decision_comments)에 먼저 쌓임 → 문서 정리 때 `- 결과:`로 옮김
- 미룰 땐 `## 보류`로 옮기고 `- 보류 이유:` 줄
- 회의 전에 낸 의견: `#### 의견` 블록 (결과 아님, 정하면 지우고 `- 결과:`로)
- 상황 설명이 필요하면 `#### 무슨 상황` 블록 (어떤 화면에서 누가 무엇을 할 때인지)
- 정한 것을 다시 열 땐 `## 정할 것`으로 옮기고 `- 결과:` 줄은 지운 뒤 "출처"에 다시 연 이유(예: D20에서 다시)를 적음
- 번호는 다시 쓰지 않음 (보드가 펼침 상태를 번호로 기억함)
