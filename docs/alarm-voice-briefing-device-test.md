# 알람 음성 브리핑 — 휴대폰 직접 확인 순서

자동 시험(서버 · 앱 · Kotlin 단위 시험 · DB 검사)으로는 **실제 소리 · 잠금화면 · 비행기 모드**를 확인할 수 없습니다.
아래 순서대로 한 번씩 해 보고, "예상 결과"와 다르면 항목 번호와 함께 알려 주세요.

## 0. 준비 (한 번만)

1. 이 브랜치(`feat/AI-alarm-voice-briefing`)로 만든 **개발용 APK**를 설치합니다.
   GitHub → Actions → "안드로이드 빌드 검사" → 이 브랜치의 성공한 실행 → 요약 아래 APK 링크(3일 보관).
2. 서버 준비(팀에서 한 번): 개발용 Supabase에 마이그레이션 적용 + `alarm-briefing` 함수 배포. 안 했으면 2번 이후 항목은 "브리핑 없음 대체"만 확인됩니다.
3. 폰 설정 → 일반(시스템) → **텍스트 음성 변환(TTS)** → 기본 엔진(예: Google 음성 서비스) → 언어 **한국어**,
   **음성 데이터 설치**(다운로드)까지 해 둡니다. 인터넷 없이 읽으려면 이 데이터가 있어야 합니다.
4. 앱 로그인 → 설정 → 알람 점검에서 알림 · 정확한 알람 · 전체 화면 알림 권한을 모두 켭니다.
5. 알람 음량(폰 볼륨의 "알람")을 중간 이상으로 둡니다.

일정은 아래 값으로 만들면 시각 계산이 쉽습니다 (지금이 오전 9:00이라고 하면):
- 일정명 "팀플 회의", 시각 = **지금 + 40분**, 이동시간 10분(직접 입력), 준비 20분
- 준비물 "노트북" 추가, 기상 · 출발 알람 켬
- 기상 알람을 **지금 + 3분**으로 직접 바꿔 저장 → 앱을 한 번 닫았다 열기(브리핑 미리 받기)

## 1. 기본 동작 (인터넷 있음)

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 1-1 | 기상 알람이 울릴 때까지 기다림 | 알람음이 먼저 나고, 곧 알람음이 작아지며 한국어 음성이 "좋은 아침이야~ … 오늘은 오전 9시 40분 팀플 회의 일정이 있어 … 챙길 것: 노트북 …"을 읽음. 다 읽으면 알람음이 다시 커짐 |
| 1-2 | 전날 밤 AI 대화에서 "내일부터 일찍 일어나고 싶어"라고 말한 뒤 다음 날 알람 | 1-1 문장 앞쪽에 "어제 오늘부터는 일찍 일어나겠다고 했잖아."가 들어감. 대화를 안 했으면 이 문장이 없음 |
| 1-3 | 화면의 [5분 미루기] → 다시 울릴 때 | 2단계: "야, 이제 진짜 일어나야 해 …" — 1-1과 같은 폰 목소리인데 **확실히 높고 빠름**(높낮이 1.7 · 속도 1.5) |
| 1-4 | 한 번 더 미루기 → 다시 울릴 때 | 3단계: Gemini **엄마 목소리(Gacrux)**가 소리치며 "야, 근데 이제 진짜 일어나야 돼 …". 개인화 음성을 못 받았으면 앱에 든 3단계 예비 음성(gemini_stage4_fallback.wav, "야! 너 안 일어나?! …"), 그것도 안 되면 폰 TTS |
| 1-5 | 해제 | 소리 · 진동 · 음성이 모두 멈춤 |
| 1-6 | 출발 알람 시각(약속 − 이동 − 여유) | 알림이 뜨고 "오전 9시 40분 팀플 회의 갈 시간이야. 챙길 것: 노트북. 이제 출발하자!"를 한 번 읽음. 상태바에 "출발 안내를 읽고 있어요"가 잠깐 보였다 사라짐 |

## 2. 긴급(지각 위험 · 여유 5분 이하)

일정 시각 = 지금 + 35분, 이동 10분, 준비 20분 → 여유가 5분이 되는 때 = 지금 + 5분 정도.
기상 알람을 지금 + 2분으로 두고 앱을 열었다 닫은 뒤:

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 2-1 | 첫 울림 (여유 약 13분) | 1단계 문장 (아직 긴급 아님) |
| 2-2 | 5분 미루기 → 다시 울림 (여유 0분 이하) | **미룬 횟수와 상관없이** 4단계: Gemini **긴급 목소리(Kore)**가 다급하게 "야! 너 안 일어나?! 지금 안 일어나면 진짜 늦어! …" (1.2배 빠르게). 개인화 음성이 없으면 앱에 든 4단계 예비 음성(gemini_urgent_sample.wav), 그것도 안 되면 같은 문장을 폰 TTS. 3단계 음성이 섞이지 않음 |
| 2-3 | 설정 → AI 음성 브리핑 → "가장 강하게"를 "강하게(3)"로 두고 2-2 반복 | 긴급이어도 3단계 문장까지만 |
| 2-4 | 일정 중요도를 "평소"(LOW)로 바꿔 2-2 반복 | 중요도와 상관없이 똑같이 긴급 |

## 3. 인터넷 없음 · 비행기 모드 (가장 중요)

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 3-1 | 0번 준비 후 앱을 한 번 열어 브리핑을 받음 → **비행기 모드 켬** → 기상 알람 기다림 | 정해진 시각에 알람음 + 진동 + 1-1과 같은 브리핑 음성 (인터넷 필요 없음) |
| 3-2 | 비행기 모드 그대로 미루기 2번 | 2단계 → 3단계로 음성이 바뀜 |
| 3-3 | 비행기 모드 그대로 2번 표의 긴급 상황 | 4단계로 바뀜. 미리 받아 둔 Gemini 음성이 있으면 그 음성, 없으면 앱에 든 4단계 예비 음성(인터넷 필요 없음) |
| 3-4 | **비행기 모드에서** 새 알람이 걸린 직후(브리핑을 한 번도 못 받음) 울리게 함 | 알람음 + 짧은 기본 문장("좋은 아침이에요. 오늘 첫 일정은 …"). 한 번 미루면 "알람을 한 번 미뤘어요 …"가 앞에 붙음, 두 번 미루면 3단계 예비 음성(엄마 목소리). 지각 위험(4단계)은 알 수 없어 안 나옴 |
| 3-5 | 비행기 모드에서 해제 · 미루기 | 둘 다 바로 됨 |
| 3-6 | 비행기 모드에서 앱을 열기 | 알람 목록 · 예약이 지워지지 않음 |

## 4. 한국어 TTS가 없거나 실패할 때

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 4-1 | TTS 설정에서 한국어 음성 데이터 삭제(또는 언어를 영어만) → 비행기 모드 → 알람 | **알람음 · 진동은 그대로** 울림. 음성만 안 나옴(8초 안에 포기) |
| 4-2 | 4-1 상태에서 3 · 4단계 | Gemini 음성(개인화 · 예비 WAV)은 폰 TTS와 무관하게 나옴 |

## 5. 화면 잠금 · 백그라운드 · 앱 종료 · 재부팅

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 5-1 | 화면을 끄고 잠근 채 기다림 | 잠금화면 위에 알람 화면 + 소리 + 음성 |
| 5-2 | 앱을 홈 버튼으로 내려 둠 | 같음 |
| 5-3 | 최근 앱 목록에서 앱을 **밀어서 닫음** | 같음 (알람은 폰 시스템이 울림) |
| 5-4 | 알람 전에 폰을 **재부팅**(인터넷 없이도) | 재부팅 뒤에도 정해진 시각에 울리고 브리핑도 나옴. 꺼져 있던 동안 지난 알람은 울리지 않음 |
| 5-5 | 설정 → 앱 → Re:Spec Alarm → **강제 종료** | ⚠ 안드로이드 규칙상 강제 종료한 앱의 예약 알람은 **모두 취소**됨 — 앱을 다시 열어야 다시 걸림. 우리 앱이 고칠 수 없는 운영체제 제한 |
| 5-6 | 배터리 최적화가 아주 강한 제조사 폰(일부 절전 모드) | 몇 분 늦게 울릴 수 있음 — 설정 → 배터리 → 앱 최적화 해제 권장 (운영체제 제한) |

## 6. 진동 · 음량 설정 유지

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 6-1 | 일정의 알람 강도에서 진동을 "없음"으로 → 중요도 "매우 중요" → 긴급 상황 | 긴급이어도 진동 없음 |
| 6-2 | 폰의 알람 음량을 낮게 → 알람 | 음성도 알람 음량 기준으로 나옴(앱이 알람 계획의 비율만큼 맞추고 끝나면 원래대로) |
| 6-3 | 출발 알람 음성 | 알람 음량으로 나오므로 **무음 · 진동 모드에서도 들림** (의도한 동작 — 문제면 알려 주세요) |
