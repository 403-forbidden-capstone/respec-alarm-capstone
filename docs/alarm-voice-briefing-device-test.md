# 알람 음성 브리핑 — 휴대폰 직접 확인 순서

자동 시험(서버 · 앱 · Kotlin 단위 시험 · DB 검사)으로는 **실제 소리 · 잠금화면 · 비행기 모드**를 확인할 수 없습니다.
아래 순서대로 한 번씩 해 보고, "예상 결과"와 다르면 항목 번호와 함께 알려 주세요.

## 0. 준비 (한 번만)

1. 이 브랜치(`feat/AI-alarm-voice-briefing`)로 만든 **개발용 APK**를 설치합니다.
   GitHub → Actions → "안드로이드 빌드 검사" → 이 브랜치의 성공한 실행 → 요약 아래 APK 링크(3일 보관).
   JS만 바뀐 새 커밋은 다시 설치하지 않고 PC에서 `npx expo start`로 붙으면 바로 반영됩니다. 네이티브(`modules/` · `plugins/` · `app.json` · 네이티브 패키지)가 바뀌었을 때만 빌드를 다시 돌립니다. 네이티브가 그대로면 다시 돌려도 빌드 없이 같은 APK가 나옵니다(#514).
2. 서버 준비(팀에서 한 번): 개발용 Supabase에 마이그레이션 적용 + `alarm-briefing` · `briefing-device` · `alarm-briefing-device` 함수 배포. 안 했으면 2번 이후 항목은 "브리핑 없음 대체"만 확인됩니다.
3. 폰 설정 → 일반(시스템) → **텍스트 음성 변환(TTS)** → 기본 엔진(예: Google 음성 서비스) → 언어 **한국어**,
   **음성 데이터 설치**(다운로드)까지 해 둡니다. 인터넷 없이 읽으려면 이 데이터가 있어야 합니다.
4. 앱 로그인 → 설정 → 알람 점검에서 알림 · 정확한 알람 · 전체 화면 알림 권한을 모두 켭니다.
5. 알람 음량(폰 볼륨의 "알람")을 중간 이상으로 둡니다.

일정은 아래 값으로 만들면 시각 계산이 쉽습니다 (지금이 오전 9:00이라고 하면):
- 일정명 "팀플 회의", 시각 = **지금 + 40분**, 이동시간 10분(직접 입력), 준비 20분
- 준비물 "노트북" 추가, 기상 · 출발 알람 켬
- 알람 강도에서 **말소리를 "약"으로 직접 고름** (1번 표는 1단계부터 확인. 자동이면 평소 · 중요 일정은 "중" = 2단계부터, 매우 중요는 "강" = 3단계부터)
- 기상 알람을 **지금 + 3분**으로 직접 바꿔 저장 → 앱을 한 번 닫았다 열기(브리핑 미리 받기)

## 1. 기본 동작 (인터넷 있음)

|---|---|---|

| 1-3 | 화면의 [5분 미루기] → 다시 울릴 때 | 2단계: "이제 정말 일어나야 해. …"(느낌표 없음, 일정 · 준비물 · 다짐 다시 안내) — 1-1과 같은 폰 목소리인데 **확실히 높고 빠름**(높낮이 1.7 · 속도 1.5) |
| 1-4 | 한 번 더 미루기 → 다시 울릴 때 | 3단계: Gemini **엄마 목소리(Gacrux)**가 소리치며 "야! … 일정 있잖아! … 챙겨야지! …"(일정 · 준비물 · 다짐 모두). 개인화 음성을 못 받았으면 앱에 든 3단계 예비 음성(gemini_stage4_fallback.wav, "야! 너 안 일어나?! …"), 그것도 안 되면 폰 TTS |
| 1-5 | 해제 | 소리 · 진동 · 음성이 모두 멈춤 |
| 1-6 | 출발 알람 시각(약속 − 이동 − 여유) | 알림이 뜨고 "오전 9시 40분 팀플 회의 갈 시간이야. 챙길 것: 노트북. 이제 출발하자."를 한 번 읽음 (느낌표는 읽지 않음). 상태바에 "출발 안내를 읽고 있어요"가 잠깐 보였다 사라짐 |

## 1-B. 말소리별 시작 단계 · 미루기 (여유가 넉넉한 일정)

말소리만 바꾸고 앱을 한 번 열었다 닫으면(브리핑 다시 받기) 다음 울림부터 시작 단계가 바뀜. 여유 5분 이하여도 단계가 올라가지 않음

| # | 말소리 | 첫 울림 → 미루기 1 · 2 · 3번 |
|---|---|---|
| 1B-1 | 약 | 1단계(부드러운 폰 TTS) → 2 → 3(엄마 Gemini) → 3 |
| 1B-2 | 중 | 2단계(빠르고 단호한 폰 TTS) → 3 → 3 → 3 |
| 1B-3 | 강 | 3단계(엄마 Gemini)부터 → 3 → 3 → 3 |
| 1B-4 | 중 · 강 첫 울림 | "미뤘다"는 말이 나오지 않음 |

## 2. 긴급(지각 위험 · 여유 0분 이하)

남은 여유 = 약속 − 지금 − 준비 − 이동 (버퍼 없음). 일정 시각 = 지금 + 35분, 이동 10분, 준비 20분 → 여유가 0분이 되는 때 = 지금 + 5분 정도.
기상 알람을 지금 + 2분으로 두고 앱을 열었다 닫은 뒤:

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 2-1 | 첫 울림 (여유 약 3분) | 말소리 시작 단계 문장 (아직 긴급 아님 — 여유 5분 이하여도 3단계로 안 올림) |
| 2-1b | 미루지 말고 계속 울리게 둠 (여유 0분이 지남) | 울리는 도중 2초 안에 4단계 긴급 음성으로 바뀜 (말소리 약 · 중 · 강 모두) |
| 2-2 | 5분 미루기 → 다시 울림 (여유 0분 이하) | **미룬 횟수와 상관없이** 4단계: Gemini **긴급 목소리(Kore)**가 다급하게 "야! 지금 안 일어나면 (이 알람의 일정) 늦는다고! …"(Gemini 대본) 또는 "야! 너 안 일어나?! 지금 안 일어나면 진짜 늦어! …"(템플릿) (1.2배 빠르게). 개인화 음성이 없으면 앱에 든 4단계 예비 음성(gemini_urgent_sample.wav), 그것도 안 되면 같은 문장을 폰 TTS(느낌표는 읽지 않음). 3단계 음성이 섞이지 않음 |
| 2-3 | 설정 → AI 음성 브리핑 → "가장 강하게"를 "강하게(3)"로 두고 2-2 반복 | 긴급이어도 3단계 문장까지만 |
| 2-4 | 일정 중요도를 "평소"(LOW)로 바꿔 2-2 반복 | 중요도와 상관없이 똑같이 긴급 |

## 3. 인터넷 없음 · 비행기 모드 (가장 중요)

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 3-1 | 0번 준비 후 앱을 한 번 열어 브리핑을 받음 → **비행기 모드 켬** → 기상 알람 기다림 | 정해진 시각에 알람음 + 진동 + 1-1과 같은 브리핑 음성 (인터넷 필요 없음) |
| 3-2 | 비행기 모드 그대로 미루기 2번 | 2단계 → 3단계로 음성이 바뀜 |
| 3-2b | 말소리 "강"으로 브리핑을 받은 뒤 비행기 모드 → 첫 울림 | 첫 울림부터 3단계 (시작 단계는 폰에 저장돼 인터넷 없이 유지) |
| 3-3 | 비행기 모드 그대로 2번 표의 긴급 상황 | 4단계로 바뀜. 미리 받아 둔 Gemini 음성이 있으면 그 음성, 없으면 앱에 든 4단계 예비 음성(인터넷 필요 없음) |
| 3-4 | **비행기 모드에서** 새 알람이 걸린 직후(브리핑을 한 번도 못 받음) 울리게 함 | 알람음 + 짧은 기본 문장("좋은 아침이에요. 오늘 첫 일정은 …"). 한 번 미루면 "알람을 한 번 미뤘어요 …"가 앞에 붙음, 두 번 미루면 3단계 예비 음성(엄마 목소리). 지각 위험(4단계)은 알 수 없어 안 나옴. 브리핑이 없어도 예약에 실린 말소리로 시작 (약 1 · 중 2 · 강 3 — 강이면 첫 울림부터 3단계 예비 음성) |
| 3-5 | 비행기 모드에서 해제 · 미루기 | 둘 다 바로 됨 |
| 3-6 | 비행기 모드에서 앱을 열기 | 알람 목록 · 예약이 지워지지 않음 |

## 8. 새벽 백그라운드 갱신 (#515)

앱을 열지 않아도 새벽 4시 대화 정리 결과(어제 다짐)가 아침 알람에 들어가는지 봅니다. 기상 알람은 **다음 날 오전 7시 이후**로 둡니다.
갱신 작업 기록: `adb shell dumpsys jobscheduler | grep -A3 briefing_refresh` (작업) · `adb shell dumpsys alarm | grep alarmcore-refresh` (걸린 시각).
새벽까지 기다리기 어려우면 개발 폰 시각을 03:55로 옮겨(자동 시간 끔) 4:10을 지나게 해도 됩니다 — 서버 정리는 실제 시각 기준이라 이때는 "정리 전"으로 보여 refresh_at 재시도까지 확인됨.

| # | 하는 것 | 예상 결과 |
|---|---|---|
| 8-1 | 로그인 후 앱을 한 번 열었다 닫음 → `dumpsys alarm`에서 갱신 시각 확인 | 다음 기상 알람 날 **04:10 (KST)** 에 `alarmcore-refresh` 예약이 걸림. 기상이 04:15 전이면 예약 없음 (기존 브리핑으로 울림) |
| 8-2 | 밤에 AI 대화(다짐) → [완료] 없이 **최근 앱에서 밀어 닫음** → 화면 잠금 · 충전 안 함 → 아침 알람 | 1~4단계 문장에 그 다짐이 들어감. 앱을 연 적이 없어도 됨 |
| 8-3 | 밤에 AI 대화 → **[완료]** | 정리가 끝나자마자 브리핑을 다시 받음 (새벽 갱신을 기다리지 않음) |
| 8-4 | 알람을 먼저 맞춰 둔 뒤(앱 열기) → 나중에 AI 대화만 하고 앱을 닫음 | 8-2와 같음 — 갱신 예약은 알람을 걸 때 이미 들어가 있음 |
| 8-5 | 새벽에 **비행기 모드** → 기상 5분 전 이후에 끔 | 갱신을 못 해도 알람은 정상, 전날 받아 둔 브리핑으로 울림 (기존 브리핑이 지워지지 않음) |
| 8-6 | 새벽에 비행기 모드 → 06:00에 끔 (기상 07:30) | 인터넷이 생기면 바로 받음(작업이 네트워크를 기다림) → 다짐이 든 브리핑 |
| 8-7 | 갱신 시각 전에 **재부팅** | 재부팅 뒤에도 04:10 예약이 다시 걸림 (`dumpsys alarm`) |
| 8-8 | 기상 알람 시각을 바꿈 · 끔 · 지움 (앱에서) | 바꾸면 새 날짜의 04:10으로, 끄거나 지우면 갱신 예약 · 대기 작업이 없어짐 |
| 8-9 | 로그아웃 → 다른 계정 로그인 | 앞 계정의 갱신 예약 · 브리핑 · 기기 키가 남지 않음. 새 계정으로 다시 열면 새 키를 받음 |
| 8-10 | 배터리 절전 모드(제조사 강한 절전 포함)를 켜고 8-2 | 갱신이 늦거나 못 돌 수 있음 — 그래도 **알람은 제시간에** 전날 브리핑으로 울림 |
| 8-11 | 알람이 울리는 중 · 미룬 뒤 | 갱신이 돌지 않음 (울리는 브리핑이 중간에 바뀌지 않음). 울리는 순간 네트워크 · Gemini 호출 없음 |
