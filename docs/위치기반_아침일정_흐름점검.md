# 위치 기반 아침 일정 안내: 흐름 점검과 개선 계획

기준: 2026년 11월 2일, 저장소 기본 브랜치 `6106e96`. 웹 시연은 가짜 데이터, 기기 시험은 별도 시험 계정과 기존 개발용 안드로이드 앱을 사용했다. 화면을 본 사실과 코드상 추정, 아직 시험하지 못한 항목을 구분한다.

## 흐름과 확인 상태

| 단계 | 확인한 내용 | 아직 필요한 확인 |
| --- | --- | --- |
| 가입과 온보딩 | 웹 가짜 모드에서 아이디, 닉네임, 잠귀, 집 위치 건너뛰기, 준비·여유 시간, 이동 수단, 시간표 건너뛰기, 개인정보·권한 안내를 거쳐 첫 일정 만들기까지 진행했다. | 실제 신규 계정 가입, 기기 권한 허용·거부·설정 복귀, 집 주소 입력과 좌표 저장은 처음부터 다시 확인해야 한다. 기존 시험 계정을 초기화하지 않았다. |
| 일정 입력과 계산 | 웹 가짜 모드에서 일정 만들기·계산·저장·상세 화면으로 이동했다. 안드로이드 기존 앱에서 시험 일정을 만들어 장소 검색과 준비·출발·도착 시각을 확인한 뒤 삭제했다. | 실제 길찾기 실패·대체 시간, 출발지·목적지 수정, 반복 일정 및 다른 시간대, 최신 앱의 계산 결과를 검증해야 한다. 지도 준비 중 및 주소 역조회 실패가 관찰됐지만 원인은 확인되지 않았다. |

## 확인된 코드상 문제와 이번 개선

1. **취소된 반복 회차가 감시 계획에 남을 수 있다.** `mobile/src/features/location/register.ts`의 참여 조건 조회에 `exception_kind` 필터가 없고, `supabase/functions/_shared/edit-run.ts`는 한 회차 삭제 시 해당 값을 `CANCELED`로 남긴다. 취소 회차가 집 이탈을 차지하거나 불필요한 목적지 감시를 만들 가능성이 있다. 일정 목록과 같은 조건을 서버 조회에 적용하고 조회 조건을 시험한다. 실제 기기에서의 발생 여부는 미확인이다.
2. **앱을 켜 둔 채 일정을 변경하면 감시 계획 갱신이 늦을 수 있다.** 위치 동기화는 로그인 직후와 앱 복귀 때 실행되지만 일정 변경 후 알람 동기화 완료 이벤트를 구독하지 않았다. 해당 이벤트에 연결해 제한 시간과 관계없이 재조회하고, 구독 해제와 중복 실행을 시험한다. 네트워크나 권한 실패 시 자동 감지가 보장되지는 않는다.

## 후속 확인과 결정이 필요한 항목

- 삭제 직전 잡힌 출발 후보와 오프라인 보관 기록을 취소 회차에 쓰지 않게 할지, 어느 시점의 취소를 기준으로 할지 정하고 서버·기기 경쟁 조건을 함께 시험한다. 조회 목록에 없다는 이유만으로 기록을 폐기하면 조회 범위 밖 일정까지 잃을 수 있어 이번 수정에서 임의로 폐기하지 않는다.
- 집 위치가 없거나 위치 권한을 거부한 사람에게 자동 감지 불가와 대체 수동 기록을 어떤 단계에서 안내할지 화면별로 확인한다.
- 웹 목업에서 보이는 지도와 실제 기기 지도·장소 검색 실패의 원인을 재현해 분리한다.
- 아침 알람의 발화 품질과 길찾기 실제 응답을 계정·권한이 준비된 기기에서 시험하고 실패 시 사용자에게 보이는 대안을 확인한다.
- 기기 위치 감시는 운영체제와 제조사 절전 정책에 영향을 받는다. 강제 종료·재부팅·절전·오프라인을 구분한 검증이 필요하다. [Expo 위치 문서](https://docs.expo.dev/versions/v57.0.0/sdk/location/)도 안드로이드에서 앱이 종료된 경우의 제약을 설명한다.

## 이번 검증 범위

변경한 조회와 동기화 연결을 자동 시험하고 타입·정적 검사·전체 앱 시험을 실행한다. 자동 시험은 서버의 실제 필터나 운영체제 위치 신호를 대체하지 않는다. 사용자 데이터 삭제 없이 실행 가능한 기기 시험을 추가하되, 최신 개발용 앱으로 시험하지 못한 구간은 완료로 표시하지 않는다.

2026년 11월 2일 결과: 타입 검사 통과, 정적 검사 오류 없음·기존 경고 2건, 전체 시험 119개 묶음·2,000개 통과. 첫 전체 시험은 종료 뒤 비동기 경고가 발생해 종료 코드가 실패였고, 출력 제한을 적용한 재실행은 정상 종료했다. 시험용 에뮬레이터의 기존 네이티브 앱은 최신 알람 화면 변경을 포함하지 않는다.

같은 날 `respec_p5`에 기존 개발용 앱을 열고 이 변경 브랜치의 개발 서버를 연결해 홈 화면이 실행되는 것을 확인했다. 개발 서버의 로컬 전용 연결은 에뮬레이터에서 실패해 일반 연결로 다시 열었다. 이 확인은 앱 시작 확인이며, 취소 회차의 실제 서버 조회 결과나 위치 이동을 통한 출발·도착 확인은 아니다.
