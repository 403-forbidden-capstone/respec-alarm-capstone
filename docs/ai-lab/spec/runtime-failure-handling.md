## 4. 비용 · 지연 계산

- 걸린 요청 지연 = 원 p50 + 재시도 p50
- 추가 평균 비용 = r × 호출당 비용
- 재시도가 또 걸릴 가능성은 무시 (재시도 상한 1회, 대체 처리가 받음)

| 추가 호출 기대값 | T1 0.09 (상한 0.15) + T5 0.02 ≈ **0.11번** (상한 0.17) |
| 추가 지연 기대값 | +0.35초 (한 대화 전체, 상한 +0.5초) |
| 추가 비용 기대값 | 약 $0.00004 / 대화 (상한 $0.00006) → 한 달(30대화) **$0.0012** (상한 $0.0018) |
| 지연 목표(5초)에 미치는 영향 | T1 걸린 2.9%는 5.0초로 목표 경계. **지연 목표 안에서 재생성이 불가능한 호출은 시간 제한(8초) 넘기면 대체 처리** |

- T1 재생성이 지연 목표를 깨는 문제: 기상 직후 응답은 5초 목표인데 T1 p50 2.5초 + 재생성 2.5초 = 5.0초. 목표에 걸리는 곳에서는 **재생성 대신 후처리로 고칠 수 있는 위반만 고치고, 나머지는 그대로 내보내는** 선택이 있음 (위반이 읽는 데 해롭지 않으면). 우선순위: 지어낸 숫자 · 거짓 저장 말은 재생성, 저장 약속은 시간이 없으면 그대로 내보내고 기록만 남김. 109는 어느 쪽이든 서버가 문장을 넣고 뺌.

## 5. 이 표로 결정이 필요한 것

1. T1 재생성 정책 (B 제안) 과 5초 목표 경계 처리
2. T2 정답 없는 항목을 '저장하고 수정 가능'으로 둘지, 컨디션 메모 · 사유 태그도 확인 카드로 받을지 (현재 제안은 전자)
3. 109 판단의 주체 = **서버 규칙** (T2 `safety_flag` + 위험어 목록)으로 확정할지
4. 비서(ASSIST) 호출은 생각 토큰이 상한을 먹으므로 상한 · effort를 따로 정할지
5. Gemini 이식 시험 때 위 표의 비율을 다시 재기 (구조 실패 · 거절 · 잘림부터)
