# 최종 시험 — 역할마다 기준 팔 vs 최종 판, 시험용 사람 4명 · 시험용 시나리오 48개, 한 번

> 10/14 시작. 사용자가 "남은 실험을 끝내고 정리까지" 맡기며 최종 시험도 허락함. 모델은 Claude Haiku 5.5(판정 · 검수는 Sonnet 5.5). **운영 모델 Gemini는 못 써 봄 → 모든 동작은 Gemini 미확인.**
> 시험용 사람은 이 문서에서 **시험 1 ~ 시험 4**로만 씀 (이름 · 사람 번호 · 시나리오 번호는 쓰지 않음). 시험용 결과를 보고 프롬프트 · 서버 규칙을 고치지 않음 — 이 문서가 끝이고, 고치려면 새 개발용 실험부터.

### 0.2 읽는 규칙

- 개발용에서 쓴 지표 · 정의 · 채점 코드를 그대로 씀. 시험용이라고 새 지표를 만들지 않음.
- 판 하나당 1번(추천 비서만 2번)이라 표본이 작음. **대화 48개 · 기록 단위 수십 개 · 일기 12일 · 코칭 16건 · 추천 날 수십 개 · 무음 12개.** 개발용의 반복 2회 폭(흔들림)보다 작은 차이는 '구분 안 됨'으로 적음.
- 개발용과 방향이 다르면(개발용에서 좋았는데 시험용에서 같거나 나빠짐) 그 자리에 적고 숨기지 않음. 같은 방향이면 '개발용 결과가 시험용에서도 보임'까지만 말하고 더 크게 말하지 않음.
- 최종 판 구성은 개발용 결론 그대로: 대화 B(+E2 서버 고침 3가지가 이미 코드에 있음), 추출 T2.v2, 일기 T4.v1.1(조건부), 코칭 T5.v1.2(조건부), 추천 HYBRID.v1.1(조건부), 무음 n1.
- 개발용 B 결과(E1)는 E2 서버 고침(기상 늘 확인 목록에 · 정정된 기록 '처리됨' 줄) **전** 값이고, 시험용 B는 그 고침이 **들어간** 코드라 같은 조건이 아님. 이 차이는 결과에서 따로 적음.
- 설문(귀찮음)은 안 돌림 (예산). 사람 눈 확인(30건)은 안 거쳤으므로 판정 기반 수치는 참고치.
- 예산 상한 $7 (이 단계). 부족하면 대화 답 + 추출 → 일기 · 코칭 → 추천 비서 → 대답 없을 때 순으로 줄이고 표본 크기를 적음.

3. **추천 비서 상한 +15분**: 개발용 진단에서는 맞음을 올렸고 시험에서는 내림(28일 44.0 → 40.9). 서버 지침 후보 '더하는 총량 상한'은 근거가 한쪽뿐.
