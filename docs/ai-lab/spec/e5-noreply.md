> 개발용 사람 p01~p08만 썼고 시험용 4명은 모델을 한 번도 안 불렀음. 구성은 E1 B 팔(T1.v1.3 + 서버가 확인할 기록을 고름 + 시각을 말로) + 끝 추출 T2.v2 그대로.

1. 받아쓰기 결과가 비면 **무음**. 사용자 턴으로 남기되 추출은 안 부름. 서버가 연속 무음을 셈.
2. 1번째 무음: 처리 결과에 `무음 1번째` 줄 → T1이 직전 물음을 한 번만 짧게 다시 물음. 2번째 무음: `무음 2번째` 줄 → T1이 마무리, **앱이 그 답 한 번 읽고 대화를 끝냄**(T1이 `end`를 안 내도).

4. 이탈하면 그때까지 대화로 T2.v2를 한 번만. 위 3과 같은 기준으로 저장.

### 3.1 무음 (NO_REPLY)

무음 시나리오 12건 (`data/v3/scenarios-noreply.json`, 개발용 p01~p08, 바탕은 옛 유형의 하루, 읽어 줄 기록 2개 이상인 날만):

|---|---|---|---|---|---|

| s3-nr-002 | S2 | NORMAL | 태오 p06 · 1 | 5 | 준비 시간 확인 |

- 무늬: **S2** = 처음부터 무음 2번 (사용자 말 1 · 2가 빈 글, 가상 유저를 안 부름) · **M2** = 사용자 말 1은 가상 유저가 하고(새 일정 · 일정 변경을 말함) 2 · 3이 무음 — AI의 '저장할까요?'에 무음 · **S1** = 무음 한 번 뒤 AI가 다시 물으면 가상 유저가 답함.
- 팔: **n0** = T1이 대화 기록에서 `나 1: (말 없음)`만 봄 · **n1** = n0 + 서버 처리 결과에 `무음` 줄을 줌. 둘 다 T1.v1.3 본문은 그대로 (프롬프트 안 바꿈).
- 같은 시나리오를 여러 번 돌려 표본을 늘림 (n0: S2 5건 × 3번, M2 4건 × 2번 = 23대화 · n1: S2 5 × 3, M2 4 × 2, S1 3 × 1 = 26대화). **같은 시나리오의 반복은 서로 독립이 아님**. n0에는 S1을 안 돌림(예산).
- 실행기 규칙 (`converse.ts`의 `silence` 옵션, 안 주면 예전과 똑같음):
  - 무음 턴은 가상 유저 · 턴별 추출(T2)을 안 부르고 처리 결과는 '바뀐 것 없음'.
  - **연속 2번째 무음 뒤 AI 답 한 번**으로 대화를 끝냄. 무음 직후 AI가 `end=true`를 내면 거기서 끝.
  - n1만: 처리 결과에 아래 줄이 들어감 (`view.ts`, 가장 최근 무음이 아니면 '이미 지나감').

| 줄 | 글 |
|---|---|
| 무음 1번째 | `- 무음: 사용자가 대답하지 않음 (1번째) — 직전 물음을 한 번만 짧게 다시 물을 것, 재촉 · 사과 없이 (서버가 정함)` |
| 무음 2번째 | `- 무음: 사용자가 또 대답하지 않음 (2번째) — 더 묻지 말고 짧게 마무리하고 end를 true로 (서버가 정함)` |

- 끝 추출: 대화 전체를 T2.v2(E2 그대로: 기본 화면 · medium)로 한 번. 무음 줄은 `나 N: (말 없음)`으로 대화에 들어감 (가장 위험한 쪽).

### 3.2 중간 이탈 (DROP_OFF)

- 새로 대화를 만들지 않고 E1 B 대화(`runs/e1-b1` · `runs/e1-b2`, 같은 72 시나리오를 두 번 돌린 것)를 **자름**. 자기 전 · 검수 정답 있음 · AI 말 4개 이상인 개발용 대화 40건 중 12건을 코드가 골랐음 (유형을 돌려 가며, 같은 유형은 id 순 — 결과를 보기 전에 정함, `pickDropoffConvs`).
- 자르는 자리 5곳: **A1 · A2 · A3** = AI 말 1 · 2 · 3번째에서 끊김(사용자가 못 답함) · **U1 · U2** = 사용자 말 1 · 2번째 직후 끊김(AI가 못 답함). 끊긴 뒤에도 원래 대화가 이어졌던 경우만. 12건 모두 5곳이 다 맞아 12 × 5 × 2묶음 = 120호출.
- 정답 = 그 자리까지의 사용자 말로만 만든 표: `buildGold(시나리오, 검수 판정[0..u), …)` — t2.ts 턴별 정답과 같은 규칙 (u = 잘린 대화의 사용자 말 수, A1은 0이라 **정답이 비어 있음**).

### 3.3 보는 것의 정의 (코드, `src/run/e5-lib.ts`)

| 이름 | 뜻 |
|---|---|
| 첫 무음 직후 답의 종류 | 같은 물음 다시(직전 AI 말의 물음 표시와 겹치거나 '틀린 · 기록'을 다시 말함) · 다른 물음으로(돌아보기 · 서버 질문 · 다른 되물음) · 열어 둠('편할 때 말해 주세요') · 이어 감(물음도 마무리도 없음) · 마무리(end=true) |

| 빠뜨림 · 값 다름 | 정답에 있는데 못 뽑음(FN) · 짝은 맞는데 값이 다름(NEAR) |

## 6. 결정

| 후보 | 판정 |
|---|---|
| **무음 서버 줄 2개 (n1)** | **채택 제안.** 같은 물음 다시 9% → 100%, 첫 무음 조기 마무리 22% → 0%, 둘째 무음 뒤 마무리 94% → 100%, 무음을 승낙으로 받는 말 17% → 4% (대화 수). 나빠진 곳: '아직 듣고 계신가요?' 류 확인 말이 0/23 → 4/26 대화, 다시 묻는 말이 처음 말과 글자까지 같은 경우 있음 (S2에서 2건). 확정은 사용자 |
| 무음 처리를 T1 프롬프트 본문에만 넣기 | 안 해 봄. n0 결과(본문만으로는 규칙대로 안 함)가 서버 줄이 필요하다는 근거. 본문에 줄을 따라 하라는 글은 넣지 않음 (카드 ③ 본문 그대로) |
| 무음 턴에 추출을 부르지 않음 | **채택.** 빈 글이라 부를 이유가 없음. 끝 추출이 무음을 확인으로 적지 않아서(0/49) 끝 추출 입력에는 `(말 없음)` 줄을 넣어도 됨 (빼도 되는지는 안 가름) |
| 둘째 무음 뒤 AI 답 한 번 읽고 앱이 끝냄 | **채택.** T1이 알아서 끝낸 것이 n0 17/18 · n1 23/23이라 서버가 `end`를 강제해도 어긋남 없음 (n0 한 건은 돌아보기를 또 물음 → 서버가 끊어야 함) |
| 이탈: 그때까지 대화로 T2.v2 한 번, save가 CONFIRMED가 아닌 것은 저장 안 함 | **채택.** 120호출 저장 과장 0 · 기록 확인 지어냄 0(눈으로 읽음) · 사용자가 한 말 97% 맞게 뽑음 |
| 읽어 준 기록에 답이 없으면 UNCLEAR | 이미 추출 프롬프트가 그렇게 냄(S2 30호출 중 21). 서버는 UNCLEAR · 없음을 '확인 필요'로 두고 CONFIRMED · CORRECTED · DENIED만 저장 상태로 바꿈 |

사용자가 정할 것 (실험으로 못 정함):
1. **무음 판정 시간 N초와 마이크 열림 규칙** (이번엔 '빈 받아쓰기 결과가 왔다'까지만 다룸). 앱이 N초 안에 아무 글자도 안 오면 빈 결과로 넘기는 구현은 앱 쪽 일.
2. **이탈 판정 기준** (화면 꺼짐 · 앱 백그라운드 몇 분 뒤 끝 추출을 부를지).
3. **마무리 답에 '저장 못 한 것' 한 줄을 서버가 줄지**: 확인 못 받은 일정 · 기록이 있을 때 마무리 답의 3/8(n1)이 그 사실을 안 알림. 서버가 `저장 안 됨: 친구 생일 저녁 (확인 못 받음)` 줄을 주고 T1이 한마디로 전하게 하는 후보 (미검증).
4. 무음 줄에 '있는지 묻지 말 것'을 더할지 ('아직 듣고 계신가요?' 4/26, 미검증).

- **무음은 빈 글만.** 진짜 받아쓰기는 '음' · '어' 같은 군말이나 잡음 글자 한두 자를 보낼 수 있고, 말했는데 못 알아들은 경우와 구별이 어려움. 그건 안 다룸. 무음 판정 시간(N초) · 마이크 규칙도 안 잼.
- 가상 유저 없이 대본으로 무음을 만듦. 실제 사용자는 AI가 다시 물을 때 이미 폰을 내려놨을 수 있어 둘째 무음 뒤 마무리 문장을 읽어 주는 것 자체가 필요한지는 모름.
- 표본: 무음 시나리오 12건 · n0는 9건 × 2~3번(23대화), n1은 12건 × 1~3번(26대화). **같은 시나리오 반복은 독립이 아님.** S1은 n1에만 3대화, n0에는 없음. 3%p 아래 차이는 못 가림.
- 무음 대화의 정답은 가상 유저 자기보고(검수 없음), 이탈은 E1 검수 정답(Sonnet 1회, 사용자 30건 확인 전)을 자른 것.
- 이탈은 **E1 대화를 자른 반사실**. 실제로 중간에 나가는 사용자는 대화 방향이 달랐을 수 있음. 끊는 자리는 코드가 정한 5곳이고 12대화가 2묶음에서 같은 시나리오라 독립 표본은 12.
- 끝 추출은 호출당 1번(반복 없음). E2에서 잡음 폭이 0.015였고 이번 지어냄 수는 0~2라 비교할 수준은 아님.
- 코드 눈(정규식)은 눈으로 다시 읽어 보정함: '말씀이 없으셔도 괜찮아요'가 재촉말로, '다시 말해 주세요' 마무리가 물음으로 걸리는 것을 고쳐 정의를 바꿈 (표는 고친 뒤 값). 눈으로 읽은 건 n0 첫 무음 23건 · n0 둘째 무음 18건 · n1 전부.
- 채점기는 정답에 없는 UNCLEAR 기록을 지어냄으로 세므로 표에서는 따로 뺌 (뺀 값이 '그 밖 지어냄'). 채점기가 중립으로 치는 취침 시각 되풀이(ECHO)가 무음 7 · 이탈 34개 있음 — 사용자가 취침 기록을 맞다고 한 대화에서 나온 것으로 보이고(전수 확인은 안 함), AI 말만 있는 54호출에서는 1개.
- 장부 총합에 E4 등 다른 작업이 섞이므로 E5 돈은 실행 이름(e5-)으로만 셈.

## E5. 대답이 없을 때 (무음 · 중간 이탈)

**한 줄 결론**: T1.v1.3 프롬프트만으로는 사용자가 말이 없을 때 규칙(한 번만 다시 묻고 또 없으면 끝냄)을 안 따르지만(직전 물음을 다시 묻는 답 2/23), **서버가 '무음 n번째' 줄을 주면 26/26이 한 번 다시 묻고 둘째 무음 뒤 23/23이 마무리**함. 끝 추출(T2.v2)은 무음을 확인으로 적지 않았고(0/49), 대화 도중 끊겨도 확인 못 받은 기록 · 약속을 지어내지 않았음(120호출, 저장 과장 0).

**왜 했나**
- 지금까지 시나리오에는 짧은 답 · 말로 거절 · 원탭 무응답 · 대화 없는 날은 있었지만 'AI가 물었는데 아무 말이 없음'과 '대화 도중 앱이 닫힘'이 없었음.
- 무음은 앱 규칙(안)을 먼저 정하고 T1이 따르는지 봄: 무음 → 한 번만 짧게 다시 물음 → 또 무음이면 종료, 확인 못 받은 기록은 '확인 필요'로 남김. 이탈은 그때까지 대화로 끝 추출 한 번.

**누구로 해 봤나** — 개발용 8명. 무음 시나리오 12건(서윤 · 도현 · 하은 · 민준 · 지우 · 태오 · 수아 · 준혁), 이탈은 E1 B 대화 12건 × 5곳 × 2묶음. 시험용 4명은 안 씀.

**대화로 보면**: 5.1 ~ 5.4 (`spec/spec/e5-noreply.md`) — 같은 무음을 줄 없이 / 줄 있이 비교한 대화(태오 s3-nr-002, 민준 s3-nr-007), 무음 한 번 뒤 답한 대화(도현 s3-nr-011), 같은 대화를 세 곳에서 자른 것(하은 s3-dev-016).

**결과**

|---|---|---|
| 첫 무음 뒤 직전 물음을 다시 묻는 답 | 2 (9%) | **26 (100%)** |
| 다른 물음으로 넘어가거나(돌아보기 · 서버 질문) 이어 감 | 11 + 4 | 0 |
| 첫 무음 뒤 바로 마무리 | 5 (22%) | 0 |
| 둘째 무음 뒤 마무리(end=true) | 17/18 (94%) | 23/23 (100%) |

| 끝 추출 (T2.v2) | 호출 | 결과 |
|---|---|---|
| 무음 대화 (말이 하나도 없는 30 + 말 · 무음 섞인 19) | 49 | 기록을 확인 · 정정 · 부정으로 지어냄 0, 약속 save가 CONFIRMED로 나온 것 0 (UNCONFIRMED 16/16), 읽은 기록은 UNCLEAR로 표시(30호출 중 21) |

**그래서**: 무음 서버 줄 2개 채택 제안, 둘째 무음 뒤 AI 답 한 번 뒤 앱이 종료, 무음 턴은 추출 안 부름, 이탈은 그때까지 대화로 T2.v2 한 번(save가 CONFIRMED가 아닌 것은 저장 안 함). 사용자가 정할 것: 무음 판정 시간(N초) · 이탈 판정 기준 · 마무리 답에 '저장 못 한 것' 줄을 줄지.
**한계**: Gemini 미확인 · 무음은 빈 받아쓰기 글만 · 같은 시나리오 반복은 독립이 아님(무음 12건, 이탈 12건) · 이탈은 E1 대화를 자른 반사실 · 무음 대화의 정답은 가상 유저 자기보고. 든 돈 $0.45 (장부, e5-).
