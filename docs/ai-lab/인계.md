## D7 영향 (10/13 팀 결정: 음성 대화 = 실시간 Gemini Live)

이 실험은 1턴(받아쓰기 글 → 답 · 추출) 전제. 실시간이면 아래처럼 갈림 — 실시간 경로는 Gemini Live 키가 있어야 확인 가능(미검증).

| 실험 | 실시간에서 | 이유 |
|---|---|---|
| E0 받아쓰기 정리 | 해당 없음 | Live가 소리를 직접 받음 |
| E1 대화 답 | 내용은 그대로 · 넣는 방식만 바뀜 | 서버가 고른 확인할 기록 · 시각을 말로 · '고쳐 둘게요' 금지는 세션 시작 지시문으로. 턴마다 서버 처리 결과는 도구 호출(function calling)로 받아야 함 |
| E2 추출 | 끝 추출(T2.v2) 그대로 · 빠른 추출(T2F) 바뀜 | 대화 끝 글로 T2.v2 한 번은 같음. 턴 중 서버 처리는 T2F 대신 Live 도구 호출 |
| E3 · E4 | 그대로 | 대화 밖(밤 · 기록 기반) 호출 |
| E5 무음 · 이탈 | 다시 정해야 함 | 무음 판정은 Live 음성 감지가 함. '무음 1 · 2번째' 줄 대신 앱 타이머 · 세션 종료 규칙. 이탈 시 끝 추출 1번은 그대로 |
## 남은 일 (순서)

1. **피드백 루프** — `피드백루프_계획.md`. 한 바퀴 = 바꿀 것 1개 → 개발용 전체 흐름 재실행 → 점수표 → 채택 · 보류 · 버림. 시험용 4명은 쓰지 않음(이미 최종 시험 한 번 씀)
2. **직접 대화(온보딩 → 채팅) 내부 테스트 화면** — 계획 7.1절
3. **Gemini 확인** — 키가 생기면 같은 시험지(개발용 파일 · `data/v3/e3-t4-days.json` · `runs/e1-b1-e3-ids.txt` 등)로 다시 돌려 생각(thinking) 설정 · 출력 형식 · 지연 확인. 카드 각 장 'Gemini로 옮길 때' 목록
4. 새 개발용 실험 후보 (선택, 피드백 루프 바꿀 것으로도 가능): ① T5.v1.2의 지어냄 · 규칙 통과 ② 위험한 날 일기 처리(코칭을 비워도 일기에 위험한 말이 순화돼 들어감) ③ 추천 비서 총량 상한 +15분과 '모두 +N분'(`피드백루프_계획.md`의 1순위)

## 정해야 할 것

- D7: 실시간 경로에서 위 'D7 영향' 표대로 갈지 — 특히 E1 지시를 세션 시작에 넣는 방식, 턴 중 서버 처리를 도구 호출로 받을지, E5 무음을 앱 타이머로 할지
- E1: 대화 0.4턴 늘어나는 것 받아들이나 (추천: 받아들임) · 알람이 여러 개 바뀌면 AI가 몇 개 말하나 (추천: 기상만 말하고 "나머지도 맞춰 뒀어요")
- E2: 한 턴 시점 설계(빠른 추출 ∥ 답, 처리 결과 있으면 답 다시) 승인 · T2F에 할 일(todos) 더하기 (약 $0.08)
- E3: T4.v1.1을 쓸지(평가 말을 막고 싶을 때만, 판정 이득 없음 · 최종 시험에서도 이득 확인 못 함) · T5.v1.2를 쓸지(최종 시험에서 지어냄 · 규칙 통과가 나빠 보임) · 위험한 날 서버가 코칭 · 루틴을 비우는 것과 일기까지 다룰지 (서버 지침 40 · 45) · 7일 패턴 줄이 그날 기록과 모순될 때 서버가 빼는 것 (39)
- E4: HYBRID를 앱에 넣을지 — 넣는다면 알람 자동 변경 없이 이유 한 줄 + 근거 날짜 + '받기 · 그대로' 카드로만 (서버 지침 53) · 총량 상한을 +15분으로 둘지(개발용은 맞음을 올리고 최종 시험은 내림, 47) · 7장 규칙 보강 반영할지(알람 뒤 기상 확인 늦어짐 상수 반영 · 앱이 잰 출발이 평균 6.6분 늦은 것 보정 · 위치를 끈 사람 통계, 51) · 기본 준비시간 · 여유를 늘리는 쪽(AI 없이 '모두 +8분'이 맞음 66.2%였던 것)을 따로 검토할지 · 이미 여유 있는 사람은 AI 조정을 끌지 (52)
- E5: 무음 서버 줄 2개 채택 · 무음 판정 시간(N초)과 마이크 열림 규칙 · 이탈 판정 기준(화면 꺼짐 · 앱 백그라운드 몇 분 뒤 끝 추출을 부를지) · 마무리 답에 '저장 못 한 것' 줄을 서버가 줄지(미검증) · 무음 줄에 '있는지 묻지 말 것'을 더할지('계세요?' 류가 개발용 4/26 · 시험 2/12, 미검증)
- 판정기가 사람 눈과 맞나 — 사람이 30건 확인 (약 20분). 지금 사람 기준 맞음 같은 판정 수치는 모두 참고치
- 실제 기록이 쌓이면(11월) 추천 비서를 섀도 비교(7.22)로 다시 확인

## 주의

- 시험용 사람 4명 · `s3-test-*` · 무음 시험용 시나리오는 문서 · 화면에 안 씀(최종 시험 문서는 '시험 1 ~ 4'). 모델을 더 부르지 않음 — 최종 시험은 이미 한 번 썼고, 다시 하려면 사용자가 "최종 다시"라고 할 때만
- 실험 결과를 다른 모델 학습 데이터로 쓰지 않음 (Anthropic 이용 정책)
- 사용자 말은 안드로이드 받아쓰기를 흉내 낸 잡음(`src/lib/stt-noise.ts`) — 실제 녹음 샘플로 확인한 적 없음
- 가상 사용자 · 14~42일 기록은 만든 데이터라 "숨은 습관을 찾았다"는 결과는 실제 정확도의 증거가 아님
- 이번에 고친 도구: `src/run/t4.ts --judge-only <run>`(저장된 일기 출력에 빠진 판정만 붙임), `e3-report.ts --t4days`, 분석 화면이 무음 시나리오 대화(개발용)를 읽음
