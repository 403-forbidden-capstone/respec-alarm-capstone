# 피드백 루프 계획 (10/15, 준비만 — 만들기는 다음 시작 때)

## 무엇

사용자가 한 번 부를 때마다 한 바퀴. **한 바퀴 = 바꿀 것 1개 → 개발용 전체 흐름 재실행 → 점수표 → 채택 · 보류 · 버림 → 기록.**

- 부르는 법: 채팅에서 "피드백 루프 돌려 — <바꿀 것>" (안에서는 `npm run loop -- --change <이름>`)
- 기준 = 지금 채택판 묶음(대화 B · T2.v2 · T4.v1.1 · T5 · 추천 RULE/HYBRID · 무음 n1). 채택되면 기준이 바뀜
- 판정 규칙은 지금과 같음: 이득이 2회 흔들림보다 크고, 사람 8명 중 나빠진 사람이 없을 때만 채택
- 시험용 4명은 루프에서 안 씀. 루프 몇 바퀴 뒤 사용자가 "최종 다시"라고 할 때만 한 번
- 기록: `loop/기록.md`에 바퀴마다 한 줄(바꾼 것 · 점수 변화 · 결정 · 든 돈), `/lab`에 '루프' 칸

## 점수표 (한 장)

| 영역 | 핵심 지표 | 사람별로도 |
|---|---|---|
| 추천 · 알람 | 맞음 · 지각 · 너무 넉넉함 %, 낭비 분 | 예 |
| 대화 답 | 틀린 자동 기록 정정률 · 규칙 어김 · 턴 수 | 예 |
| 추출 | F1 · 지어냄 | — |
| 일기 · 코칭 | 지어냄 % · 사람 기준 맞음 % | 예 |
| 무음 · 이탈 | 다시 묻기 · 무음을 '네'로 받음 · 지어냄 | — |

바꾼 것과 관계없는 영역은 이전 값 재사용(돈 아낌). 바꾼 영역 + 그 뒤 단계만 다시 돌림.

## 주로 바꿔 볼 것 (추천 순)

| 순서 | 바꿀 것 | 왜 | 1바퀴 비용 |
|---|---|---|---|
| 1 | **모두 +N분 여유** (N = 0 · 4 · 8 · 12) vs 사람별 조정 | E4에서 '모두 8분 일찍'이 맞음 66%로 어느 판보다 높았음 — 개인화가 정말 이기는지 확인 | $0 (코드만) |
| 2 | **가정 흔들기**: 출발 감지 지연(0 · 6.6 · 10분), 알람 뒤 폰 보는 시간 분포 | '+8분' 결과가 시뮬레이터 가정 탓인지 확인. 가정이 바뀌어도 결론이 같아야 믿음 | $0 |
| 3 | **7장 규칙 보강**: P80 → P70 · P90, 기상 확인 지연 상수, 출발 감지 보정 | 규칙(RULE)이 지금 계획보다도 못했음 — AI 없이 고칠 수 있는지 | $0 |
| 4 | **HYBRID 상한** (+10 · +15 · +20분) | 같은 자료에 맞춘 +15가 새 날에서도 맞는지 | 약 $0.4 |
| 5 | **코칭 입력 줄이기**: 7일 패턴 줄 빼기 · 서버가 근거 한 줄 지정 | T5 지어냄 38%, 패턴 한 줄로 모두에게 같은 코칭 | 약 $0.3 |

그다음 후보(나중): 확인할 기록 개수(1 · 2 · 3, 턴 수와 정정률 맞바꿈), 알람 몇 개 말할지, 무음 줄 문구.

**1~3은 API를 안 써서 바로 여러 바퀴 돌릴 수 있음** — 먼저 이것부터 추천.

## 다음 시작 때 만들 것

1. 실행기 `src/run/loop.ts` — 바꿀 것 설정(`loop/changes.json`) 읽기 → 영역별 실행기 호출 → 점수표 · 결정
2. 점수표 기준값 = 지금 채택판 결과(개발용) 저장
3. 시뮬레이터 가정을 설정으로 빼기(2번용) — 기존 생성 결과는 그대로 두고 새 파일로
4. `/lab` 루프 칸 · `loop/기록.md`
