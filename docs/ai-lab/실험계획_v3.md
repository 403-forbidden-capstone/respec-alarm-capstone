# 실험계획 v3 — 음성 받아쓰기 기준 · 앱 지점별 프롬프트 카드

> 10/10 초안. 사용자 피드백 반영: 숫자 말고 사람 · 대화로 이해되게, 입력은 음성 받아쓰기, 받아쓰기 정리도 LLM 역할로 실험, 결론은 "이 지점에서 이렇게 시키면 이렇게 동작함".
> 이전 계획 = `실험계획_v2.md` (참고용)

## 0. 지금까지 실험을 돌아보면

**의도대로 된 것** — 그대로 가져감
- 가상 유저(Sonnet)가 AI(Haiku)와 대화하고, 다른 검수자가 "실제로 무슨 말을 했나"를 다시 읽어 정답을 만드는 방식
- 서버가 숫자 · 저장 · 알람을 정하고 AI는 말만 하는 구조, 그 구조를 흉내 내는 서버 스텁
- 라운드 1에서 배운 것 (아래 '이어 가는 출발점')

**의도와 어긋난 것** — 이번에 바꿈
1. **사용자 말이 타이핑체였음.** 4가지 말투 중 1가지만 받아쓰기체였고, 나머지는 "ㅇㅇ 맞아", "ㄴㄴ" 같은 채팅 말. 실제 앱은 음성이라 이런 말이 안 들어옴
2. **받아쓰기 정리 단계가 없었음.** 실제로는 받아쓰기 결과를 LLM이 한 번 정리한다고 보는데, 그 역할을 실험하지 않았음
3. **결과가 숫자 위주였음.** F1 · 승률만 있고 "이 사람이 이렇게 말했고 AI가 이렇게 답했는데 이게 맞았다"가 없었음
4. **결론의 대상 모델이 달랐음.** 결론은 운영 모델(Gemini)에 쓸 지침이어야 함. 이번에도 Gemini 키 없이 Haiku로만 실험하므로, 카드마다 "Gemini에서는 확인 안 됨"을 적고 옮길 때 주의점을 따로 씀

**이어 가는 출발점** (라운드 1에서 확인된 것)
- 109 안내는 위험한 말에만, 대화당 1번
- 확인받을 기록은 서버가 골라 주는 쪽이 틀린 기록을 고칠 기회를 크게 늘림
- 첫마디는 기록 확인만, 서버 질문은 다음 턴, 마무리 전에 돌아보기 1번 → 더 많이 알아내지만 대화가 조금 길어짐
- 추출은 "코치가 말한 기록에 '응'이면 모두 확인", "시간을 잡아먹은 일만 이유로"가 효과 있었음
- 숫자(알람 몇 분)는 규칙이 정하고 AI는 사연 있는 날을 짚고 설명하는 역할이 맞아 보임

## 1. 앱에서 AI가 하는 일

```
[자기 전 · 기상 후 대화]
사용자가 말함 → 폰 받아쓰기(날 텍스트) → ① 받아쓰기 정리 → ② 추출(저장할 것 뽑기)
                                                          ↓
                                       서버: 계산 · 확인 필요 판단 · 알람 바꾸기
                                                          ↓
                                                 ③ 답 문장 → 폰이 읽어 줌(TTS)
[밤 01:00]  ④ 일기 · 코칭 · 응원 · 루틴 제안
[자기 전 / 알람 설정 때]  ⑤ 알람 시간 추천 비서 (쌓인 기록으로 "내일은 10분 일찍")
```

| 지점 | 언제 | AI가 받는 것 | AI가 내는 것 | 서버가 정하는 것 |
|---|---|---|---|---|
| ① 받아쓰기 정리 (T0, 새로) | 사용자가 말할 때마다 | 받아쓰기 날 텍스트 + 앱에 있는 일정 이름 | 정리된 문장 + 잘 안 들린 곳 표시 | 없음 |
| ② 추출 (T2 · T3) | 말할 때마다 | 정리된 대화 + 오늘 기록 · 일정 | 일정 · 할 일 · 기록 정정 · 이유 · 기분 (JSON) | 저장할지, 확인 받을지, 알람 시각 |
| ③ 답 (T1) | 말할 때마다 | 오늘 기록 · 서버 질문 · 서버 처리 결과 | 1~2문장 답 | 무엇을 물을지, 숫자 |
| ④ 일기 · 코칭 (T4 · T5) | 밤 01:00 | 하루 기록 + 대화 요약 | 일기 · 코칭 · 응원 · 루틴 의도 | 루틴 제안 자격 |
| ⑤ 추천 비서 | 자기 전 | 쌓인 기록 (서버 집계) | 제안 카드 1장 + 근거 날짜 | 기본 준비시간(7장 규칙) |

## 2. 가상 유저 다시 만들기

### 2.1 사람 카드 — "어떤 사용자를 가정했는지"를 전부 적음

앱 흐름(7장: 잠 → 알람 → 기상 확정 → 준비 → 출발 → 이동 → 도착 → 대화) 순서로 칸을 나눔. 칸마다 **진짜 모습**(가상 유저만 앎)과 **앱이 보는 기록**(앱이 실제로 잴 수 있는 것)을 따로 적음. 이 둘의 차이가 AI가 맞혀야 할 것임.

예: **서윤 (p01, 개발용)**

| 흐름 | 진짜 모습 | 앱이 보는 기록 |
|---|---|---|
| 기본 | 21세 · 경영학과 3학년 · 존댓말, 차분함, 기록이 틀리면 정확히 고쳐 말함 · 협조적 · 평소 기분 3/5 | 프로필 |
| 시간표 | 월 · 수 10:30 재무관리(경영관), 화 13:00 마케팅 팀플, 목 09:00 마케팅원론, 금 14:00 카페 알바(신촌역) | 반복 일정 |
| 잠 | 보통 00:30쯤 잠. 자기 전 폰을 20 ~ 30분 봄. 시험 전날은 2시 넘어 잠 | 마지막 화면 꺼짐 → 취침 추정 (폰을 보다 잠들면 정확, 일찍 폰 끄고 누우면 늦게 잡힘) |
| 알람 | 알람을 두어 번 미룸(5분씩). 월요일엔 세 번 | 미루기 횟수 |
| **기상 · 폰** | **알람을 끄고 누운 채 폰을 10 ~ 15분 보다가 일어남.** 화요일 1교시 없는 날은 30분 넘게 봄 | 해제 후 첫 잠금 해제 = '기상 확정' 시각 → **실제로 몸을 일으킨 시각보다 10 ~ 15분 이름** |
| 준비 | 일어나서 출발까지 50분 (씻기 · 옷 · 간단히 먹기). 화 · 목에 머리를 감으면 +12분. 늦으면 아침을 거름(−10분) | 기상 확정 → 출발 감지 사이 시간. '머리 감기' 이유는 대화에서 말한 날만 찍힘 (3번 중 1번 꼴) |
| 출발 | 집(경기 고양) 현관 → 역까지 걸어 8분 | 위치 권한 켬 → 집 반경 150m를 벗어난 시각. 쓰레기 버리러 잠깐 나가면 오감지 (5분 안에 돌아오면 앱이 걸러 냄) |
| **이동** | 3호선 → 2호선 환승, 길찾기 API 예상 58분인데 **실제 평균 65분** (환승 걸음이 느림). 월요일 아침은 +5분 더 붐빔. 비 오는 날 +8분 | 길찾기 예상 vs 실제(출발 → 도착 감지). 이 차이가 '개인 이동 보정' |
| 도착 | 경영관까지 역에서 걸어 6분 | 목적지 반경 150m 진입 시각. 약속 + 3분 넘으면 지각 |
| 여유 | 여유 15분으로 설정 | 설정값 |
| 대화 | 자기 전 대화엔 잘 응함, 기상 후엔 짧게 | 대화 기록 |
| 권한 | 위치 켬 · 사용 기록(폰 사용) 켬 · 캘린더 안 씀 | 자동 감지 가능 범위 |

- 12명 모두 이렇게 만들되 일부러 다양하게: 알람 듣자마자 바로 일어나는 사람 / 끄고 다시 자는 사람(재수면 → 재알람) / 알람 전에 깨서 폰 보는 사람, 걸어서 5분 기숙사생 / 자차 / 버스 환승, 위치 · 폰 사용 권한을 끈 사람(자동 기록이 비고 원탭 응답만 있음)
- 그날그날의 '숨은 사실'(오늘 늦은 진짜 이유, 내일 새 일정 등)도 사람 카드에 붙여서 보임
- **기상 판정 · 이동 보정에서 생기는 오차가 대화에서 확인받을 거리**가 됨. 예: "7시 2분에 일어나셨어요" ← 실제론 폰 보다가 7시 15분에 일어남 → 사용자가 고쳐 주면 '기상 ~ 준비 시작 간격'(7.1.1 `pre_prep_minutes`)을 배움

### 2.2 말은 두 겹 — 하려는 말 / 받아쓰기 결과

| 하려는 말 (정답) | 받아쓰기 결과 (AI가 실제로 받는 것) |
|---|---|
| 어제 재무관리 수업에 10분쯤 늦었어요. 버스가 안 와서요. | 음 어제 그 재무 관리 수업에 한 십 분 늦었어요 버스가 안 와 가지고 |
| 내일 6시 반에 로봇 동아리 있어요. | 내일 다섯 시 아 아니 여섯 시 반에 로봇 동아리 있어요 |
| 8시 10분 출발은 아니에요, 편의점 잠깐 간 거예요. | 여덟 시 십 분은 아니고 편의점 잠깐 간 거예요 |

받아쓰기 = 마이크로 들은 말을 글자로 바꿔 주는 기능(음성 인식, STT). 앱은 마이크를 기본 기능으로 붙일 예정이라 **안드로이드 기본 음성 인식(구글)** 을 가정함.

받아쓰기에 넣을 잡음 (실제 엔진 없이 흉내 냄 — 한계로 적음)
- 문장부호 거의 없음, 숫자는 섞여 나옴('7시 30분' 또는 '일곱 시 반', '십오 분')
- 군말('음', '어', '그'), 말 바꾸기('다섯 시 아 아니 여섯 시 반')
- 비슷한 소리로 잘못 들음('스터디' → '스타디', '경영관' → '경영 관'), 고유명사 틀림
- 가끔 끝이 잘림
- 채팅 말('ㅇㅇ', 'ㄴㄴ', 'ㅠㅠ')은 **없음**

## 3. 실험 목록 (순서대로)

각 실험의 결과는 "사람 몇 명 중 몇 명"과 대화 예시로 보고함.

### E0. 받아쓰기 정리 (T0, 새 역할)

**알고 싶은 것**: 받아쓰기 결과를 LLM이 한 번 정리하면 뒤 단계(추출 · 답)가 나아지나? 어디까지 고쳐야 하나?

**대화 흐름 예시**
```
받아쓰기: 음 내일 그 마케팅 원론 아홉 시 거 있잖아요 그거 휴강이래요 그리고 한 십오 분 일찍 깨워 주세요
정리:     내일 9시 마케팅원론 휴강이래요. 그리고 15분 일찍 깨워 주세요.
          [잘 안 들린 곳: 없음]
→ 추출: 마케팅원론(내일 09:00) 취소 확인 필요 · 기상 15분 앞당김 확인 필요
```

**비교하는 것**
- 정리 없이 날 텍스트를 바로 추출 · 답에 넣기
- 정리를 따로 한 번 (일정 이름 목록 없이 / 있이)
- 정리를 추출 안에서 같이 하기 (호출 1번 줄이기)

**보는 것**
- 뜻이 그대로인가 (없는 말을 만들거나 빼지 않았나)
- 시각 · 분 · 일정 이름을 맞게 바꿨나 ('여섯 시 반' → 18:30, '재무 관리' → 재무관리)
- 뒤 단계 추출이 얼마나 나아졌나
- 늘어난 시간 (대화 한 턴 5초 목표)

**통과 기준**: 정리를 거친 쪽이 추출을 더 잘하고, 지어낸 말 0, 늘어난 시간 1초 안쪽

### E1. 자기 전 · 기상 후 대화 (T1)

**알고 싶은 것**: AI가 기록을 확인하고, 서버 질문을 하고, 기분 좋게 마무리하나?

**대화 흐름 예시** (실제로 돌린 대화, 말만 음성체로 바꿈 — 시나리오 s-dev-037)

사람: **수아** (p07, 22세 영어영문학과, 가족 차로 통학 30분, 새벽 늦게 자고 아침이 힘듦, 말이 짧고 앱에 시큰둥함)
상황: 오늘 출발 기록 3개 중 20:10은 자동 감지가 틀린 것 (편의점에 잠깐 간 것). 원래 대화에선 "ㅇㅇ 다 맞아" 같은 채팅 말이었는데, 여기선 음성으로 바꿔 적음

지금 판 (A) — 틀린 기록을 고칠 기회가 없음
```
AI:  오늘은 9시 32분에 일어나셨고 알람을 2번 미루셨어요. 동아리 면접 장소엔 4시 43분에 도착하셨고요. 틀린 게 있으면 말해 주세요.
사용자: 응 다 맞아
AI:  확인해 주셔서 고마워요. 푹 쉬세요.
→ 20:10 출발(틀린 기록)은 말하지 않아서 그대로 저장됨
```

서버가 확인할 기록을 골라 준 판 (B)
```
AI:  오늘 10시 23분, 4시 17분, 8시 10분에 출발한 기록이 있어요. 틀린 게 있으면 말해 주세요.
사용자: 앞에 두 개는 맞고 여덟 시 십 분은 아니에요 편의점 잠깐 간 거예요
AI:  편의점에 잠깐 다녀온 거였군요. 오늘 하루는 어땠어요?
→ 틀린 기록이 고쳐짐. (라운드 1에선 여기서 AI가 "고쳐 둘게요"라고 약속해서 규칙을 어김 — 저장은 서버가 정하는데)
```

**비교하는 것**: 라운드 1 결과를 합친 판 vs 지금 판, 그리고 새로 — 서버가 시각을 '오후 6시 30분'처럼 말로 바꿔 넘기기, 받아쓰기 정리 결과를 받는 판 vs 날 텍스트를 받는 판

**보는 것** (사람 단위)
- 틀린 자동 기록을 고칠 기회를 줬나 (AI가 그 기록을 말했나)
- 서버 질문을 했나, 몇 번째 턴에
- 규칙을 어겼나: 한 번에 두 개 묻기, 서버가 안 한 저장을 했다고 · 하겠다고 말하기, 위험하지 않은데 109
- 사용자가 귀찮아했나, 너무 빨리 끝냈나

### E2. 대화 → 저장 데이터 (T2 · T3)

**알고 싶은 것**: 받아쓰기로 들어온 말에서 저장할 것을 빠짐없이, 지어내지 않고 뽑나?

**대화 흐름 예시**
```
사용자(정리 후): 내일 10시에 강남에서 발표 있어요. 그래서 15분 일찍 깨워 주세요.
추출:  새 일정  내일 10:00 · 강남 · 발표 · (확인 필요)
       준비시간  +15분 · 내일만
서버:  "내일 10시 강남 발표, 저장할까요?" (확인 필요) · 기상 알람 06:50 → 06:35
AI 답: 내일 10시 강남 발표를 저장할까요? 기상은 오전 6시 35분으로 바꿔 둘게요. ← 이 문장은 규칙 위반 예 (확인 전에 '둘게요')
```

**보는 것**: 사람이 말한 것 중 빠뜨린 것 · 지어낸 것 (일정 · 할 일 · 기록 정정 · 이유 · 기분 칸별), 확인 받기 전에 저장한 것

### E3. 일기 · 코칭 · 루틴 (T4 · T5)

**대화 흐름 예시**
```
그날 기록: 기상 07:12(알람 2번 미룸) · 출발 08:05 · 도착 09:08(지각 8분) · 대화 "버스가 늦게 왔어요"
일기:  알람을 두 번 미루고 7시 12분에 일어났어요. 버스가 늦게 와서 수업에 8분 늦었어요.
코칭:  버스가 늦는 날이 있으니 내일은 한 정거장 일찍 나서 보면 어때요?  ← '한 정거장'은 기록에 없는 말이라 지어냄 예
응원 (다음 날 아침에 읽어 줌): 오늘은 여유 있게 시작해 봐요.
```

**보는 것**: 기록에 없는 숫자 · 감정을 지어냈나, 문장 수, 응원이 기상 안내 뒤에 붙어도 8초 안인가 (라운드 1: 템플릿만으로 거의 8초라 따로 정해야 함)

### E4. 알람 시간 추천 비서

**알고 싶은 것**: 그 사람의 쌓인 기록을 보고 "이 사람은 이런 사람이니 내일은 이렇게"를 맞게 제안하나?

**대화 흐름 예시** (서윤, 목요일 09:00 마케팅원론 전날 밤 — 예시)
```
쌓인 기록 28일: 화 · 목은 준비가 평균 62분 (평소 50분). 이유 태그는 3번 중 1번만 '머리 감기'
7장 규칙:   준비 52분 → 기상 06:48
AI 제안:    "목요일엔 준비가 12분쯤 더 걸렸어요 (9/24 · 10/1 · 10/8). 내일은 10분 일찍 6시 38분에 깨울까요?"
다음 날 실제: 준비 61분 → AI 제안이면 안 늦음, 규칙이면 9분 늦음
```

**보는 것** (사람마다)
- 이 사람의 숨은 습관을 찾았나 — 준비(서윤 = 화 · 목 머리 감기)뿐 아니라 **이동**(길찾기보다 7분 더 걸림 · 월요일 혼잡 · 비 오는 날)과 **기상 후 폰 보는 시간**(알람 끄고 10 ~ 15분 누워 있음)까지
- 다음 날 실제와 비교해 맞았나 / 모자랐나 / 너무 넉넉했나
- 근거로 댄 날짜가 진짜 그랬나
- 같은 상황에 물어볼 때마다 같은 답인가

### 나중에 할 일 (10/12 추가) — 대답이 없을 때

지금 있는 것: 단답(TERSE) · 말로 거절(REFUSAL) · 원탭 무응답(기록 빈칸) · 대화 없는 날(T4). 빠진 것 2개를 시나리오로 더함 (개발용, 약 $0.5).

| 새 유형 | 상황 | 보는 것 |
|---|---|---|
| NO_REPLY 무음 | AI가 물었는데 아무 말이 없음 → 받아쓰기 빈 결과 | T1이 한 번만 짧게, 재촉 없이 다시 묻나 · 두 번째 무음이면 끝내나 |
| DROP_OFF 중간 이탈 | 대화 도중 앱을 닫거나 화면을 꺼서 끊김 | 끊긴 데까지의 끝 추출(T2.v2)이 확인 안 받은 것을 확인된 것처럼 지어내지 않나 |

서버 · 앱 규칙(안)은 먼저 정함: 무음 N초 → 1번 다시 물음 → 또 무음이면 종료. 확인 못 받은 기록은 '확인 필요'로 남겨 다음 대화 · 원탭으로. 이탈하면 그때까지 대화로 끝 추출 1번, 확인 안 받은 건 저장 안 함. 결과는 카드 ③ · ② · 서버 지침에 반영.
