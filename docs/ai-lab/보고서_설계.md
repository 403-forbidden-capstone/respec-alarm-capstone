# 보고서 · 분석 화면 설계

> 10/10 초안. 목표: 숫자를 몰라도 "누가 어떤 상황에서 뭐라고 했고, AI가 어떻게 판단해서 뭐라고 답했고, 그게 그 사람한테 맞았는지"를 따라갈 수 있게.

## 1. 결과물 4개

| 결과물 | 무엇 | 누가 언제 봄 |
|---|---|---|
| `실험정리.md` | 전체 실험 내용. 실험마다 왜 · 누구로 · 대화 예시 · 결과 · 결론 | 실험 끝날 때마다 한 장씩 채움 |
| `프롬프트카드/` | 앱 지점별 프롬프트 카드 5장 + 서버 지침 1장 | 마지막. 앱 개발 때 그대로 씀 |
| 분석 화면 (로컬 웹) | 사람 · 대화 · 프롬프트 버전을 클릭해 들여다봄 | 실험 돌 때마다 갱신, `npm run dash` |
| `보고서.md` | 진행 상황만 짧게 | 수시로 |

## 2. 실험정리.md — 실험 한 장의 모양

```
## E1. 자기 전 대화

한 줄 결론: 확인할 기록을 서버가 골라 주면, 틀린 자동 기록을 사용자가 고칠 기회가 6명 중 1명 → 6명이 됨.

왜 했나: (2~3줄)

누구로 해 봤나: 서윤 (통학 65분 · 화목 머리 감기 · 꼼꼼히 고쳐 말함) 외 71명. 사람 카드 → 분석 화면 링크

대화로 보면:
  바꾸기 전 — (실제 대화 4~6줄, 문제 되는 곳에 표시)
  바꾼 뒤   — (같은 상황의 실제 대화, 달라진 곳에 표시)

결과: 숫자는 "72명 중 몇 명"으로. 꼭 필요한 것만 3~5줄
  - 틀린 기록 고칠 기회: 1/6 → 6/6
  - 규칙 어김: 72명 중 9명 → 4명
  - 대가: 대화가 평균 반 턴 길어짐, 귀찮음 조금 오름

그래서 프롬프트에 넣을 말: (카드 링크 + 핵심 문장 2~3개)

아직 모르는 것: (표본이 작은 곳, Gemini 미확인 등)
```

- 전문 용어는 처음 나올 때 한 번 풀어 씀 (예: "F1 = 말한 것 중 맞게 뽑은 비율과 뽑은 것 중 맞는 비율을 합친 점수")
- 수치는 가능하면 사람 수 · 대화 수로

## 3. 분석 화면 — 앰플리튜드 비유로

> **자세한 설계는 [분석화면_설계.md](분석화면_설계.md)** (배포 사이트 `/lab`, 메뉴 · 필터 · 화면별 그림 · 데이터 묶음 · 순서). 아래는 처음 잡은 개요.

실제 사용자 데이터 보듯 가상 유저를 봄. 앰플리튜드의 '사용자 조회 · 이벤트 흐름 · 퍼널 · 코호트'에 맞춰 화면을 나눔.

### ① 홈 — 실험별 한눈에
- 실험 카드: 한 줄 결론 + 핵심 수치 2~3개 (문장형: "틀린 기록을 고친 사람 6명 중 6명, 전엔 1명")
- 버전별 막대 (예전 판 vs 새 판)
- 크레딧 쓴 돈 · 남은 돈

### ② 사람 목록 — 사용자 탐색
| 이름 | 사는 곳 · 통학 | 숨은 습관 | 말투 | 대화 수 | 문제 있던 대화 |
|---|---|---|---|---|---|
| 서윤 | 경기 환승 65분 | 화목 머리 감기 +12분, 알람 2번 미룸 | 존댓말 · 꼼꼼 | 12 | 3 |

- 필터: 개발용 / 시험용, 말투, 문제 종류(틀린 기록 못 고침 · 규칙 어김 · 이른 마무리 …)

### ③ 사람 상세 — 사용자 조회 (가장 중요한 화면)
- **가정 카드**: 이 사람을 어떤 사람으로 만들었는지 전부 (2.1절 표 그대로)
- **날짜별 타임라인**: 기상 · 미루기 · 출발 · 도착 · 지각 · 대화 · 일기 · 비서 추천을 하루 한 줄로
  ```
  10/8 (목)  기상 07:02 (2번 미룸) · 출발 07:51 · 도착 09:04 지각 4분 · 대화 3턴 · 일기 ✓
             비서 추천 "10분 일찍" → 실제 준비 61분 → 맞음
  ```
- **이 사람한테 AI가 맞힌 것 · 틀린 것**: 숨은 습관을 찾았나, 고친 기록을 제대로 담았나

### ④ 대화 상세 — 이벤트 흐름
턴마다 펼쳐서 봄. 버전 두 개를 좌우로 놓고 비교 가능.

```
[사용자 2턴]
  하려던 말   앞에 두 개는 맞고 8시 10분은 아니에요. 편의점 잠깐 간 거예요.
  받아쓰기    앞에 두 개는 맞고 여덟 시 십 분은 아니에요 편의점 잠깐 간 거예요
  정리 (T0)   앞의 두 개는 맞고, 8시 10분 출발은 아니에요. 편의점에 잠깐 간 거예요.
  추출 (T2)   기록 정정: f3 출발 20:10 → 아님 (DENIED)
  서버        f3 지움 · 저장됨
[AI 3턴]
  AI가 받은 화면   오늘 기록 · 확인할 기록 f1 f2 f3 · 서버 처리: f3 지움
  AI 생각 (요약)   사용자가 f3을 부정함 → 서버가 지웠다고 알려 줌 → 돌아보기 질문으로 넘어감
  AI 답            편의점에 잠깐 다녀온 거였군요. 오늘 하루는 어땠어요?
  검사             규칙 ✓ · 숫자 ✓ · 물음 1개 ✓
  검수자 메모      h2(감지 오류 정정) 전달됨
```

### ⑤ 흐름 — 퍼널
자기 전 대화가 단계마다 몇 명 넘어갔나, 버전별 나란히
```
대화 시작 72 → 기록 확인 받음 60 → 틀린 기록 고침 6/6 → 서버 질문 답함 17/19 → 돌아보기 49 → 끝까지 72
```
- 칸을 누르면 그 단계에서 떨어진 대화 목록 → ④로

### ⑥ 프롬프트 비교
- 버전 두 개의 바뀐 줄만 (빨강 · 초록)
- 이 변경으로 결과가 달라진 대화 목록 (좋아진 것 / 나빠진 것) → ④로

### ⑦ 추천 검증 — 비서
| 사람 | 날 | 그 사람 가정 | 규칙 값 | AI 제안 (근거) | 다음 날 실제 | 판정 |
|---|---|---|---|---|---|---|
| 서윤 | 10/9 목 | 목요일 머리 감기 +12 | 52분 | 62분 ("목요일 3번 다 12분 더") | 61분 | 맞음 |

- 근거 날짜를 누르면 그날 기록이 열림
- 같은 질문 3번에 답이 흔들렸는지도 표시

### 만드는 방법
- `runs/`의 결과 파일을 모아 화면용 데이터(`dash/data/*.json`)로 바꾸는 스크립트 + 정적 웹페이지 (설치 없이 로컬 서버로 띄움)
- 실험이 끝날 때마다 스크립트만 다시 돌리면 갱신
- 예전 실험(타이핑 대화) 결과는 '예전'으로 표시해 참고로만 넣음

## 4. 보고서.md 바꾸기

맨 위 5줄만 보면 되게:
```
지금: E1 대화 실험 중 (2/5)
방금 끝난 것: E0 받아쓰기 정리 — 정리를 거치면 일정 이름 오인식이 72건 중 9건 → 1건
다음: E2 추출
크레딧: $45 / $98
막힌 것 · 결정 필요: 없음
```
- 나머지는 실험정리.md와 분석 화면 링크. 숫자 표는 보고서에서 뺌

## 5. 정한 것 (10/10)

- 분석 화면: 로컬로 먼저 → 배포 사이트에 화면 하나로 추가 (공개 주소라 올리기 전 확인)
- 사람 상세의 가정 카드: 앱 흐름 순서(잠 → 알람 → 기상 · 폰 → 준비 → 출발 → 이동 → 도착 → 대화 → 권한)로, 칸마다 '진짜 모습'과 '앱이 보는 기록'을 나란히 (실험계획_v3 2.1절)
- 타임라인 한 줄에 기상 확정 시각과 실제로 일어난 시각, 길찾기 예상과 실제 이동시간을 같이 보여 줌 → 앱 기록이 어디서 틀렸는지 바로 보이게
