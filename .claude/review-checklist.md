# 리뷰 체크리스트 (레포 전용)

`pr-review` 스킬로 기본 검수를 한 뒤, 이 레포에서만 필요한 항목을 추가로 확인합니다. 해당 없는 항목은 건너뜁니다.

## 규칙

- PR 제목 `[파트] [유형] 작업 내용`, 본문 `Closes #이슈번호`, 브랜치 `유형/이슈번호-파트-설명`
- 이슈 범위 밖 파일을 고쳤다면 이유가 PR에 적혀 있는지
- 여럿이 같이 고치는 파일(`package.json`, 잠금 파일, `app.json`, DB 마이그레이션)이 다른 작업과 섞여 있지 않은지

## 앱 (Expo · React Native)

- 새 패키지가 `npx expo install`로 SDK 57에 맞는 버전으로 들어갔는지
- 폰 전용 기능(알람 · 알림 · 네이티브 모듈)을 웹에서 부르면 깨지므로 `.web.ts` 대체 파일이나 `Platform` 분기가 있는지
- 네이티브 모듈 · 플러그인 · `app.json` · 네이티브 패키지 변경이면 "APK 다시 받기 필요"가 PR에 적혀 있는지
- 새 권한(permissions)에 필요한 이유가 있는지
- 화면을 바꾼 PR에 캡처가 있는지

## 데이터 · 서버 (Supabase)

- 스키마 변경은 마이그레이션 파일로만 했는지
- 새 테이블에 RLS가 켜져 있고 정책이 있는지
- `service_role` 키나 외부 API 키가 앱 코드 · `EXPO_PUBLIC_` 변수에 들어가지 않았는지
- 테이블 · 칼럼 이름이 설계 문서와 같은지 (설계 문서가 레포에 있을 때)

## 알람

- 기상 시각 역산 · 알람 강도처럼 시각을 계산하는 로직이 바뀌었으면 테스트가 있는지
- 시간대(Asia/Seoul), 자정 넘김, 반복 알람, 미루기 횟수 처리
- 네이티브 알람 코드(Kotlin · 매니페스트)는 `pr-review` 스킬의 `android-native-check.md` 항목으로 봄

## 방향성 (스킬 Step 5a에서 읽을 곳)

- 연결 이슈(`Closes` · `Refs`)와 그 이슈 다음에 올 열린 이슈 — 보드 마일스톤 순서
- `docs/`의 설계 문서 (예: 알람 코어 인터페이스, 화면 ↔ 데이터 ↔ API 매핑)
- `supabase/migrations`의 스키마 — 앱이 저장하거나 서버로 보낼 값의 이름 · 모양
- 알람 코어를 바꾸면 iOS 계획(라벨 `iOS`)과 맞는지 — 함수 이름뿐 아니라 id · 비동기 여부 · 미루기 방식까지

## 기능 흐름 PR — 작업자가 직접 확인

앱 안에서 기능이 흘러가는 길은 작업자가 알고 넘어가야 함. 그래서 이런 PR은 흐름과 판단 근거를 보여 주고, 작업자가 확인한 뒤 머지함.

- 해당: 사용자 행동이나 시각이 화면 → 함수 → 저장 · 알람 · 알림 · 서버로 이어지는 길을 만들거나 바꾸는 PR. 상태가 넘어가는 규칙(울림 → 미루기 → 해제, 약속 → 역산 → 예약, 기상 확인 등)이나, 앱 동작을 바꾸는 서버 함수 · DB 트리거 포함
- 해당 아님: 디자인 값 · 부품 모양만, 문서 · CI · 설정, 동작이 그대로인 리팩토링
- 애매하면 해당으로 봄

해당이면 보고에 두 칸을 더함 (머지 판단 바로 뒤):

1. 기능 흐름 — 시작(누가 · 무엇을 · 언제)부터 끝(무엇이 어디에 남는지)까지 한 단계에 한 줄. 이 PR이 새로 만든 단계는 "(새로)", 바꾼 단계는 "(바뀜)". 실패하면 어디로 가는지도 적음
2. 판단 · 근거 — PR이 정한 값 · 규칙 · 분기(시간 · 횟수 · 기본값 · 순서 · 실패 때 동작)를 표로: 판단 / 근거 / 확인
   - 근거: 레포 문서면 `파일 경로` + 절 제목, 이슈면 번호, 스키마면 마이그레이션 파일 · 줄. 레포 밖 문서(상세설계서 등)면 문서 이름 · 장 · 절
   - 확인: 레포 안 근거는 열어서 실제로 그렇게 적혀 있는지 봄 → 맞음 / 다름(발견 사항으로) / 레포 밖이라 확인 못 함
   - 근거가 없으면 "근거 없음 — 작성자 판단"으로 적음. 근거를 지어내지 않음
   - PR 본문의 "기능 흐름 · 판단 근거" 칸이 비었거나 코드와 다르면 발견 사항으로

머지 판단은 코드 문제가 없어도 "흐름 확인 후 머지"로 적고, 보고 맨 끝에 `- [ ] 작업자가 기능 흐름 · 판단 근거를 확인함` 한 줄을 둠.

## 보고

- 한국어로, 심각도 순으로, 파일:줄을 붙여서
- 순서: 한 줄 요약 → 머지 판단 → (기능 흐름 PR이면) 기능 흐름 · 판단 근거 → 방향성 → 발견 사항 → 자가 검수 → 건너뜀
